插件开发

这一页面向第三方开发者，目标是让你只读这一页（以及它链接的 SDK 合同）就能做出一个可安装、可启动、可被 Lux 调用的插件。Lux 插件是独立进程，不是动态库：宿主通过 stdin 写入一行 JSON 请求，插件通过 stdout 写回一行 JSON 响应。语言不限，任何能读写标准输入输出并解析 JSON 的程序都可以。

本页按 src/application/plugin_protocol.rs、src/application/plugin_runtime.rs 和 src/application/plugins.rs 的当前行为校对。字段级合同以 PLUGIN-SDK.md 为准；文档与代码冲突时以代码为准，集中列在第 8 节。

先记住两件事：stdout 只能出现协议响应，调试日志写 stderr；宿主停止插件时直接终止进程，不会发送 plugin.shutdown。示例中的服务/媒体域名只使用 example.com 或 .invalid；GitHub 地址只用于仓库和 Release 示例，不包含任何真实凭据。

1. 快速开始：一个能跑的最小插件

下面是一个完整的 ip_location 插件，只用 Python 3 标准库。它实现一个方法 ip.location，返回固定结果，方便先验证进程、帧格式和安装包。真实插件应把固定结果替换为上游查询，并继续遵守同样的输入输出约束。

1.1 目录与 manifest.json

开发目录长这样。两个架构目录可以先放同一份脚本；正式发布时分别放对应架构的入口。

org.example.ip-demo/
├── manifest.json
└── binaries/
    ├── linux-x86_64/
    │   └── plugin.py
    └── linux-aarch64/
        └── plugin.py

manifest.json 放在包根目录，声明类型、分类、能力和入口模板：

{
  "formatVersion": 1,
  "id": "org.example.ip-demo",
  "name": "示例 IP 归属地",
  "description": "Lux 插件开发教程的最小示例，只返回固定结果",
  "version": "0.1.0",
  "apiVersion": 1,
  "runtime": {
    "kind": "process",
    "entrypoint": "binaries/${platform}-${arch}/plugin.py"
  },
  "type": "ip_location",
  "category": "NETWORK",
  "capabilities": ["ip.location"],
  "permissions": {
    "network": [],
    "filesystem": []
  },
  "files": []
}

1.2 入口代码

入口直接由宿主执行，所以需要 shebang 和执行权限。脚本逐行读取 stdin，逐行写 stdout；异常路径也必须返回一行 JSON，不能让进程崩溃。

#!/usr/bin/env python3
"""Lux ip_location 插件：stdin 每行一个请求，stdout 每行一个响应。"""
import json
import sys


class PluginError(Exception):
    def __init__(self, code, message):
        super().__init__(message)
        self.code = code


def handle(method, params):
    if method != "ip.location":
        raise PluginError("PLUGIN_INVALID_REQUEST", "unsupported method")
    ip = params.get("ip")
    if not isinstance(ip, str) or not ip.strip():
        raise PluginError("PLUGIN_INVALID_REQUEST", "ip is required")
    # 演示用固定结果；真实插件应在这里查询上游服务，并只返回需要的字段。
    return {
        "ip": ip.strip(),
        "country": "示例",
        "province": None,
        "city": None,
        "district": None,
        "street": None,
        "isp": "示例运营商",
        "latitude": None,
        "longitude": None,
    }


def main():
    for line in sys.stdin:
        line = line.strip()
        if not line:
            continue
        request_id = None
        try:
            request = json.loads(line)
            if not isinstance(request, dict):
                raise PluginError("PLUGIN_INVALID_REQUEST", "request must be an object")
            request_id = request.get("id")
            params = request.get("params") or {}
            if not isinstance(params, dict):
                raise PluginError("PLUGIN_INVALID_REQUEST", "params must be an object")
            result = handle(request.get("method"), params)
            response = {"id": request_id, "result": result}
        except json.JSONDecodeError:
            response = {
                "id": None,
                "error": {"code": "PLUGIN_INVALID_REQUEST", "message": "invalid JSON"},
            }
        except PluginError as error:
            response = {
                "id": request_id,
                "error": {"code": error.code, "message": str(error)},
            }
        except Exception:
            # 诊断信息只能写 stderr；stdout 只能出现协议响应。
            print("internal plugin error", file=sys.stderr)
            response = {
                "id": request_id,
                "error": {
                    "code": "PLUGIN_INTERNAL_ERROR",
                    "message": "internal error",
                },
            }
        sys.stdout.write(json.dumps(response, ensure_ascii=False) + "\n")
        sys.stdout.flush()


if __name__ == "__main__":
    main()

给入口加执行权限。通过 ZIP 安装时，宿主只会给 binaries/ 下的文件补执行位（0700）；把入口放在其他目录会在解压后丢失执行权限，这是第 8 节列出的一个实际差异。

chmod +x binaries/linux-x86_64/plugin.py binaries/linux-aarch64/plugin.py

1.3 本地 stdin 测试

不经过 Lux，直接对入口发送一条 ip.location 请求。下面命令在插件根目录执行，并要求目标机器有 python3：

cd org.example.ip-demo
printf '%s\n' '{"id":"1","method":"ip.location","params":{"ip":"8.8.8.8"}}' \
  | python3 binaries/linux-x86_64/plugin.py

预期输出恰好一行（字段顺序可能因实现不同而变化，但必须是合法 JSON，且 id 原样回显）：

{"id": "1", "result": {"ip": "8.8.8.8", "country": "示例", "province": null, "city": null, "district": null, "street": null, "isp": "示例运营商", "latitude": null, "longitude": null}}

再测一条错误输入，确认进程不崩溃、stdout 仍然只有 JSON：

printf '%s\n' 'not json' \
  | python3 binaries/linux-x86_64/plugin.py
# {"id": null, "error": {"code": "PLUGIN_INVALID_REQUEST", "message": "invalid JSON"}}
示例只返回固定结果，不能当成真实归属地数据。真实插件要自己处理上游超时、限流、鉴权和响应解析，并把失败映射到第 7 节的稳定错误码。

2. 包结构与 entrypoint

安装包是一个 ZIP。ZIP 的根目录必须直接包含 manifest.json，不能再套一层目录：

org.example.ip-demo-0.1.0-linux-x86_64.zip
├── manifest.json
└── binaries/
    └── linux-x86_64/
        └── plugin.py

aarch64 包同理，把 linux-x86_64 换成 linux-aarch64。两个包可以有相同的 manifest，入口模板会按宿主当前平台解析到对应文件。

2.1 entrypoint 规则

  • runtime.kind 目前只能是 process。
  • runtime.entrypoint 必须是包内相对路径，不能是绝对路径，不能含 ..。
  • 可以使用 ${platform} 和 ${arch} 两个占位符。Lux 运行在 Linux 时，平台值为 linux；架构值为 x86_64 或 aarch64。例如 binaries/${platform}-${arch}/plugin.py 会解析成 binaries/linux-x86_64/plugin.py 或 binaries/linux-aarch64/plugin.py。
  • 解析后的入口文件必须真实存在。入口由宿主直接执行，不经过 shell，也不会自动拼上 python3 或 sh，所以脚本要有 shebang，二进制要能直接运行。
  • ZIP 安装时只有 binaries/ 目录下的文件会被补成 0700。入口放在 bin/ 等其它目录时，解压后可能没有执行权限；目录调试时请手动 chmod +x。
  • files 可选。声明后，宿主会逐个检查文件存在且 SHA-256 匹配；不声明不会跳过入口存在性检查。

2.2 硬性打包上限

以下上限来自 plugin_runtime.rs，超出即拒绝安装或发现：

项目上限说明
ZIP 文件大小128 MiB插件商店下载也按同一上限限制
解压后总大小256 MiB按实际写出的字节计数，篡改声明的压缩包也会被拒绝
ZIP 内文件数512包含目录项；不要把缓存、测试数据或 __pycache__ 打进去
manifest.json1 MiB必须是根目录下的普通文件

2.3 打包命令

mkdir -p dist
cd org.example.ip-demo
zip -r ../dist/org.example.ip-demo-0.1.0-linux-x86_64.zip \
  manifest.json binaries/linux-x86_64
zip -r ../dist/org.example.ip-demo-0.1.0-linux-aarch64.zip \
  manifest.json binaries/linux-aarch64
unzip -l ../dist/org.example.ip-demo-0.1.0-linux-x86_64.zip

检查 unzip -l 的第一层是不是 manifest.json；如果看到 org.example.ip-demo/manifest.json，说明多套了一层目录，安装会失败。Python 入口还要求目标机器安装 Python 3；如果要面向没有 Python 的 NAS，把入口编译成对应架构的原生二进制。

3. Manifest 参考

Manifest 是宿主判断“能不能装、能不能调用、怎么渲染配置界面”的唯一依据。下面先列全部顶层字段，再列类型约束、配置字段和权限。

3.1 顶层字段

字段必填约束说明
formatVersion是固定为数字 1包格式版本，不是插件版本
id是ASCII 字母、数字、.、-、_，最长 128安装和运行时身份；推荐 org.<组织>.<名称>，不要使用保留的 org.lux.*
name是非空，最多 256 个字符管理界面显示名称
description否字符串简短描述，建议一两句话
version是恰好三段纯数字，如 1.2.3插件自身版本；1.0、1.0.0-beta 会被拒绝
apiVersion是固定为数字 1RPC 合同版本；必须是数字，不能写成字符串 "1"
runtime是{"kind":"process","entrypoint":"..."}目前只支持独立进程运行时
type是见 3.2插件类型，决定宿主调用哪些方法
category是见 3.2；省略时代码默认 SCRAPER必须与类型匹配；不要依赖默认值
providerKey否标识符，最长 64metadata 插件用于稳定引用 provider 的不透明键，不是插件 ID
aliases否最多 16 个，每个最长 64metadata 插件的旧配置兼容别名
supportedItemTypes否最多 32 个metadata 插件支持的条目类型，如 Movie、Series
supportedMediaSourceKinds否最多 8 个；只能是 LOCAL_FILE 或 STRM_URLchapter_detector 必须非空；chapters.detect 只能声明 LOCAL_FILE
capabilities是最多 64 个字符串按类型声明；代码允许省略（默认空数组），但类型校验通常要求对应能力，请始终显式声明
embyRoutes否最多 32 条；每条 {method,path,rpcMethod}声明精确的 Emby 路由；同时必须声明 emby.route 能力
configFields否字段见 3.3管理页面据此通用渲染配置表单
scheduledTasks否最多 32 个高级能力，普通第三方插件通常不需要；字段含 taskType、ownerType（GLOBAL/LIBRARY）、name、description、scheduleConfigKey、defaultSchedule、requiredConfigKeys、ownerConfigKey、resourceLimit
permissions否见 3.4网络、文件系统和登录背景图片主机声明
files否数组，元素 {path,sha256}包内文件及 SHA-256；声明后逐个校验
signature否{algorithm,keyId,value}历史兼容字段；当前安装流程不把签名作为安全保证，不要依赖
Manifest 必须是合法 JSON，字段名区分大小写；未知顶层字段当前会被忽略，拼写错误不一定会报错。SDK 文档里的 apiVersion: "1" 是字符串，按当前代码会被拒绝；请写数字 1。

3.2 类型 → 分类 → 必需能力

下表逐条对应 plugin_protocol.rs 的校验分支。分类写错会直接拒绝清单；能力名建议全部小写。

typecategory必需能力用途与备注
metadataSCRAPER代码不强制任何能力；要作为媒体库刮削器，必须声明 metadata.search，其它 metadata.* 按方法声明电影、剧集、季、集的元数据与图片；只有 metadata 类型可以声明 ratings.*
media_probeMEDIAmedia.probe对单个媒体地址做 ffprobe 类探测；宿主每次调用使用独立进程
ip_locationNETWORKip.location公网 IP 归属地查询
strm_resolverMEDIAstrm.resolve把 SMB/FTP 等原始目标解析成可播放的 HTTP(S) 地址
chapter_detectorMEDIAchapters.detect 或 chapters.lookup，二者恰好一个还必须声明非空的 supportedMediaSourceKinds；chapters.detect 只能声明 LOCAL_FILE，chapters.lookup 可声明 LOCAL_FILE 和/或 STRM_URL
danmakuMEDIAdanmaku.match；可选 danmaku.search 与 danmaku.fetch两个可选能力必须同时声明或同时不声明；其它未知 danmaku.* 会被拒绝
notificationNOTIFICATIONnotification.send通知推送；凭据只能放在唯一的 secret 配置字段

另外，emby.route 是附加能力，可以和其他类型组合（login_background 因能力必须恰好只有 login_background.get，不能再附加）；声明了 embyRoutes 就必须同时声明该能力，路由的 method 必须是 GET/POST/PUT/PATCH/DELETE/HEAD 之一，path 必须以 / 开头、最长 256 字符且不能含 ?、#、*、..。未知的 type 会被拒绝。

3.3 configFields：管理页面通用配置

宿主根据声明渲染表单，插件不需要自己做界面。字段对象支持 key、label、type、required、sensitive、description、multiple、options、optionsSource、defaultValue、minimum、maximum。

type控件规则
text单行文本最常用；不能声明 options、multiple 或 optionsSource
textarea多行文本适合列表、模板或多行说明
password密码输入建议同时声明 sensitive: true；只有 sensitive 字段会从管理 API 的 configValues 中排除。通知插件的 secret 必须是 password + sensitive: true
select下拉选择必须且只能声明 options 或 optionsSource 之一；options 最多 256 项，值/标签各最长 128；multiple: true 可多选
toggle开关布尔值
number数字可声明整数 minimum、maximum 和 defaultValue；defaultValue 必须是整数且落在范围内
image宿主托管的图片资产只允许 org.lux.login-background 在 login_background 清单中声明一个；必须可选、非敏感、无 defaultValue；值是 sha256:<64 位小写十六进制>，由管理员图片上传 API 创建，插件拿不到本地路径或图片字节

select 的 optionsSource 当前只支持 media-libraries：宿主按当前媒体库动态填充 value/label，插件不要把媒体库 ID 或路径写死在包里。其它 optionsSource 会让清单被拒绝。

"configFields": [
  {"key": "apiBaseUrl", "label": "API 地址", "type": "text",
   "required": true, "defaultValue": "https://api.example.com"},
  {"key": "apiKey", "label": "API Key", "type": "password",
   "required": true, "sensitive": true},
  {"key": "libraryIds", "label": "媒体库", "type": "select", "multiple": true,
   "required": true, "optionsSource": "media-libraries"},
  {"key": "concurrency", "label": "并发数", "type": "number",
   "defaultValue": 2, "minimum": 1, "maximum": 64},
  {"key": "mode", "label": "模式", "type": "select", "defaultValue": "fast",
   "options": [{"value": "fast", "label": "快速"}, {"value": "accurate", "label": "精确"}]}
]

key 必须是标识符（最长 64），label 非空且最多 128 个字符；同一清单里的 key 应保持唯一。除 select 外，其它类型不能声明 options、multiple 或 optionsSource。

3.4 permissions：网络、文件系统、图片主机

"permissions": {
  "network": ["api.example.com"],
  "filesystem": [],
  "imageHosts": []
}
字段上限规则
network32 个只写主机名（如 api.example.com），不要带协议、路径、端口或 @；代码会拒绝包含 /、空格、@ 的值，每项最长 255。它是能力声明，不替代插件自己的 SSRF 防护：仍要拒绝 localhost、私网、保留地址和 IP 字面量（协议明确允许时除外）
filesystem16 个目前用于声明插件需要的本地缓存名；插件不能访问 Lux 的媒体目录
imageHosts32 个只有 login_background 插件可以声明且必须非空。必须是精确 DNS 域名，不能是通配符、带端口或带路径；应只声明公网域名，不要声明 localhost、私网或 IP 字面量（当前代码对 manifest 只做格式检查，见第 8 节）；浏览器会直接请求这些 HTTPS 图片域名

3.5 providerKey、aliases 与 ratings.*

  • metadata 插件应声明稳定的 providerKey（最长 64），用于媒体库配置稳定引用 provider；aliases 用于兼容旧配置，最多 16 个、每个最长 64。
  • id 只表示安装/运行时身份，不能代替 provider 命名空间。Provider ID 是不透明字符串，插件不要假设它一定是数字。
  • ratings.lookup、ratings.batch、ratings.search 只能由 metadata 类型声明；未知的 ratings.* 会被拒绝。只声明 ratings.* 而不声明 metadata.search 的插件不能充当媒体库刮削器，宿主只会按评分合同调用它。
  • 不准备做评分插件就不要声明 ratings.*；完整写回规则见 SDK 的“评分查询调用约定”。
清单校验失败会让插件被发现/安装失败，不会进入 RPC 调用；修正 manifest 后重新安装（直接放目录的包则重启 Lux）。

4. 通信协议

协议是换行分隔的 JSON（JSON Lines），UTF-8 编码。每个请求是 stdin 上的一行，每个响应是 stdout 上的一行并以 \n 结尾；行内不能有未转义的换行。插件应逐条处理并及时 flush。

4.1 请求与响应信封

{"id":"0196b2c4-7a1e-7c3b-9f2a-2f6f7c9a1b2c","method":"ip.location","params":{"ip":"8.8.8.8"}}

成功响应必须原样回显 id，并且只带 result：

{"id":"0196b2c4-7a1e-7c3b-9f2a-2f6f7c9a1b2c","result":{"ip":"8.8.8.8","country":"美国"}}

失败响应只带 error，code 和 message 都是字符串：

{"id":"0196b2c4-7a1e-7c3b-9f2a-2f6f7c9a1b2c","error":{"code":"PLUGIN_TIMEOUT","message":"上游超时"}}
  • id 由宿主生成，插件必须原样回显；响应可以乱序返回，宿主按 id 分发。顺序处理是最简单可靠的做法。
  • result 与 error 二选一。不要同时返回，也不要在错误响应里放业务数据。
  • stdout 只能输出协议行。任何调试输出、启动横幅、第三方库日志都必须写 stderr；一行非 JSON 会让宿主把整条响应判为无效。
  • 宿主同时最多有 16 个未完成请求（MAX_PLUGIN_INFLIGHT）；如果插件严格串行处理，第 17 个请求会等前面的响应完成，属于正常背压。
  • 单个响应行上限为 4 MiB（MAX_PLUGIN_RESPONSE_BYTES），含换行前的全部字节。超过会被宿主拒绝。
  • 宿主当前会把 stderr 读走并丢弃，不写入 Lux 日志；仍建议把诊断写到 stderr，但不要依赖它被持久化。

4.2 超时与进程生命周期

场景超时说明
默认 RPC30 秒DEFAULT_PLUGIN_CALL_TIMEOUT；大多数方法使用该值
media.probe130 秒给 ffprobe/ffmpeg 留出时间；宿主使用独立进程调用
emby.route3 秒请求路径上的短超时；不要在这里做长时间上游调用
ratings.batch单批 120 秒评分批量合同的宿主超时

超时后宿主会终止插件进程，并在下一次调用时按需重启。插件不需要常驻；要能被安全地直接杀死，不能依赖退出前的清理动作保证数据一致。宿主不会发送 plugin.hello、plugin.health 或 plugin.shutdown，详见第 8 节。

5. 各类型的方法与示例

下面每个类型至少给一个请求/响应示例。字段级定义、枚举和全部可选字段以 SDK 合同为准；示例只保留理解调用所需的部分。

5.1 metadata：元数据刮削

metadata 插件按能力提供下列方法。宿主按媒体库配置选择插件，并按方法检查对应能力：

方法能力用途
metadata.searchmetadata.search搜索候选条目，返回 items
metadata.getmetadata.get按 providerId 取详情，返回 metadata
metadata.bundlemetadata.bundle一次返回详情、图片、演员、外部 ID 和预告片
metadata.imagesmetadata.images返回 images 候选
metadata.creditsmetadata.credits返回 cast/crew
metadata.externalIdsmetadata.externalIds返回 ProviderIds
metadata.trailersmetadata.trailers返回预告片候选

metadata.search 的请求字段是 itemType、name、year（可选）、language。注意：当前代码不会在搜索请求里发送 providerId，它只出现在 get/images/credits/externalIds 等详情请求中。

{"id":"m1","method":"metadata.search",
 "params":{"itemType":"Movie","name":"示例电影","year":2024,"language":"zh-CN"}}
{"id":"m1","result":{"items":[{
  "Type":"Movie","Name":"示例电影","OriginalTitle":"Example Movie",
  "ProductionYear":2024,"ProviderIds":{"Example":"movie-1"},
  "ImageUrl":"https://images.example.com/poster.jpg"
}]}}
{"id":"m2","method":"metadata.get",
 "params":{"itemType":"Movie","providerId":"movie-1","language":"zh-CN"}}
{"id":"m2","result":{"metadata":{
  "Type":"Movie","Name":"示例电影","ProductionYear":2024,
  "ProviderIds":{"Example":"movie-1"}
}}}
{"id":"m3","method":"metadata.images",
 "params":{"itemType":"Movie","providerId":"movie-1","language":""}}
{"id":"m3","result":{"images":[{
  "Type":"Poster","Url":"https://images.example.com/poster.jpg",
  "Language":"zh","Width":1000,"Height":1500
}]}}
  • itemType 可用值：Movie、Series、Season、Episode、Person、BoxSet。
  • ProviderIds 的值必须是字符串；键由插件定义（如 Example、Tmdb），Lux 只当作不透明 ID 保存。
  • 图片必须返回完整 HTTPS Url，并声明 Type、语言和可选尺寸。缺少某类媒体/能力时返回 PLUGIN_PROVIDER_NOT_FOUND，不要伪造空数据。
  • language 为空字符串表示“不限语言”，插件不得套用管理员的首选语言过滤。

5.2 media_probe：媒体探测

方法 media.probe，请求包含一个已由宿主校验的 url，以及 includeMediaInfo、includeThumbnail、thumbnailPositionPercent。插件不解析 .strm 内容，也不会收到路径或媒体库信息。

{"id":"p1","method":"media.probe","params":{
  "url":"https://media.example.invalid/video.mkv",
  "includeMediaInfo":true,
  "includeThumbnail":false,
  "thumbnailPositionPercent":30
}}
{"id":"p1","result":{
  "container":"matroska","sourceSize":123456789,
  "durationTicks":125000000,"bitrate":5000000,
  "streams":[{
    "streamIndex":0,"streamType":"VIDEO","codec":"h264",
    "language":null,"title":null,"isDefault":true,"isForced":false,
    "details":{"Width":1920,"Height":1080}
  }]
}}
  • streamType 只能是 VIDEO、AUDIO、SUBTITLE；streamIndex 非负且不能重复。
  • 结果只应包含 Lux 允许写入 media_sources/media_streams 的字段；不要返回完整 URL、认证信息或原始 ffprobe JSON。
  • includeThumbnail 为真时可返回受大小限制的 thumbnailJpegBase64；仍然受单行 4 MiB 上限约束。
  • 媒体探测专用错误码：MEDIA_PROBE_INVALID_URL、MEDIA_PROBE_TIMEOUT、MEDIA_PROBE_PROCESS_FAILED、MEDIA_PROBE_INVALID_OUTPUT。错误消息不得包含完整 URL 或 stderr。

5.3 ip_location：IP 归属地

方法 ip.location。宿主只发送已校验的公网 IP；响应中的 ip 必须与请求相同，缺失字段填 null。

{"id":"i1","method":"ip.location","params":{"ip":"8.8.8.8"}}
{"id":"i1","result":{
  "ip":"8.8.8.8","country":"美国","province":null,"city":null,
  "district":null,"street":null,"isp":"示例运营商",
  "latitude":null,"longitude":null
}}
  • 字段：country、province、city、district、street、isp、latitude、longitude。每个字段 trim 后不能为空，最多 256 个字符，不能含控制字符。
  • 整个结果超过 64 KiB 会被宿主丢弃。Lux 对成功结果缓存 24 小时、失败结果缓存 5 分钟，插件不需要自己缓存。

5.4 strm_resolver：.strm 目标解析

方法 strm.resolve。宿主把 SMB/FTP 等原始目标交给插件，插件返回可播放的 HTTP(S) 地址；不适用时返回 UNSUPPORTED。

{"id":"s1","method":"strm.resolve",
 "params":{"target":"smb://nas.example.invalid/media/movie.mkv"}}
{"id":"s1","result":{"status":"RESOLVED",
 "url":"https://media.example.invalid/movie.mkv"}}
{"id":"s1","result":{"status":"UNSUPPORTED"}}
  • 成功返回的 url 必须是无凭据、无 fragment、无控制字符的 HTTP(S) 地址，长度受限；宿主会再次校验。
  • Lux 按插件 ID 稳定顺序尝试已安装、启用且配置有效的解析器；插件可以自行判断目标是否适用。
  • 播放请求只在解析成功后临时重定向到结果地址，Lux 不代理媒体字节。

5.5 chapter_detector：片头片尾章节

只能声明 chapters.detect 或 chapters.lookup 其中一个；清单还必须声明 supportedMediaSourceKinds。检测基于音频指纹，查询基于外部 ID；插件都不能接收文件路径、URL、媒体源 ID 或任务对象。

chapters.detect 请求示例（指纹用短占位 Base64，实际是同季至少两集的 Chromaprint 点序列）：

{"id":"c1","method":"chapters.detect","params":{
  "episodes":[{
    "key":"ep-1","sampleRate":11025,"fingerprintPointDurationTicks":1238095,
    "introFingerprintBase64":"AAAAAAAAAAA=",
    "creditsFingerprintBase64":"AAAAAAAAAAA=",
    "introWindowStartTicks":0,"creditsWindowStartTicks":0,
    "introWindowDurationTicks":900000000,
    "creditsWindowDurationTicks":900000000
  },{
    "key":"ep-2","sampleRate":11025,"fingerprintPointDurationTicks":1238095,
    "introFingerprintBase64":"AAAAAAAAAAA=",
    "creditsFingerprintBase64":"AAAAAAAAAAA=",
    "introWindowStartTicks":0,"creditsWindowStartTicks":0,
    "introWindowDurationTicks":900000000,
    "creditsWindowDurationTicks":900000000
  }],
  "introWindowTicks":900000000,"creditsWindowTicks":900000000,
  "minimumMatchDurationTicks":300000000,"matchThreshold":0.8
}}
{"id":"c1","result":{"markers":[
  {"key":"ep-1","markerType":"INTRO_START","startPositionTicks":90000000,
   "name":"片头","confidence":0.92}
]}}

chapters.lookup 请求示例：

{"id":"c2","method":"chapters.lookup","params":{
  "episodes":[{
    "key":"ep-1","tmdbId":12345,"seasonNumber":1,"episodeNumber":1,
    "durationTicks":2700000000
  }]
}}
{"id":"c2","result":{"markers":[
  {"key":"ep-1","markerType":"CREDITS_START","startPositionTicks":2400000000,

]}}
  • 线上枚举值是 INTRO_START、INTRO_END、CREDITS_START（大写下划线），不是 SDK 散文里的 IntroStart 写法。
  • 时间必须落在对应窗口内，confidence 在 0–1；无数据时返回空 markers 数组。
  • chapters.detect 只能声明 supportedMediaSourceKinds: ["LOCAL_FILE"]；chapters.lookup 可以声明 LOCAL_FILE 和/或 STRM_URL。

5.6 danmaku：弹幕匹配

必需方法 danmaku.match。宿主只发送不含路径和上游地址的文件名；匹配成功时返回受大小限制的 xmlBase64，失败返回 NO_MATCH。

{"id":"d1","method":"danmaku.match","params":{
  "fileName":"Show.S01E02.1080p.mkv",
  "alternateFileNames":["Show.S01E02.mkv"]
}}
{"id":"d1","result":{
  "status":"MATCHED","provider":"dandanplay",
  "animeId":"anime-1","episodeId":"ep-1",
  "xmlBase64":"PGk+PGQgcD0iMSwxLDI1LDE2Nzc3MjE1LDAsMCwwLDAiPmhlbGxvPC9kPjwvaT4="
}}
{"id":"d1","result":{"status":"NO_MATCH"}}

可选的手动匹配能力必须同时声明 danmaku.search 和 danmaku.fetch；只声明一个的清单无效。两个方法示例：

{"id":"d2","method":"danmaku.search","params":{"query":"示例动画","limit":20}}
{"id":"d2","result":{"candidates":[{
  "provider":"dandanplay","animeId":"anime-1","animeTitle":"示例动画",
  "episodes":[{"episodeId":"ep-1","title":"第 1 集"}]
}]}}
{"id":"d3","method":"danmaku.fetch",
 "params":{"provider":"dandanplay","episodeId":"ep-1"}}
{"id":"d3","result":{"xmlBase64":"PGk+PGQgcD0iMSwxLDI1LDE2Nzc3MjE1LDAsMCwwLDAiPmhlbGxvPC9kPjwvaT4="}}
  • 搜索的 query 为 1–200 字符，limit 为 1–50；插件应只返回不超过 limit 的候选，整条响应 ≤ 4 MiB。宿主仍会按 50 个候选、每候选 180 集裁剪。
  • animeId/episodeId 最长 128，provider 最长 64，标题最长 300；空值或控制字符会被判为无效响应。
  • XML 解码后按 Bilibili/Dandanplay 结构校验，宿主负责原子写入同名 .xml 旁车；插件不能写文件。

5.7 notification：通知推送

方法 notification.send。宿主传入已按白名单过滤的 event、目标信息 target（含 allowPrivateNetwork）、非秘密配置 config，以及可选的 secret。

{"id":"n1","method":"notification.send","params":{
  "event":{
    "schemaVersion":1,"eventId":"event-1","eventType":"MEDIA_ADDED",
    "occurredAt":1700000000,"serverId":"server-1",
    "data":{"libraryId":"library-1","addedCount":1,"source":"lux",
      "title":"媒体新增","content":"新增媒体：1 个","body":"新增媒体：1 个"}
  },
  "target":{"url":"https://example.com/lux-hook","allowPrivateNetwork":false},
  "config":{"payloadFormat":"LUX"},
  "secret":"REPLACE_WITH_DEVICE_KEY"
}}
{"id":"n1","result":{"status":"DELIVERED","providerRequestId":"msg-1"}}
  • status 只能是 DELIVERED、RETRYABLE、FAILED；可选 providerRequestId、retryAfterSeconds、errorCode。
  • 插件必须自己执行私网和保留地址检查，不得放宽 allowPrivateNetwork 策略；event.data 不包含本地绝对路径、原始 .strm 目标或令牌。
  • 凭据只能来自 secret，不能进入 config、事件、日志或数据库。

通知插件的 secret 是唯一的凭据字段，必须满足：key 为 secret、type 为 password、sensitive: true、不能有 defaultValue，且最多一个。其它字段不能声明为 sensitive 或 password。通知插件的其它 configFields 属于每条通知目标，不是插件安装级配置。

{"key":"secret","label":"设备密钥","type":"password",
 "required":true,"sensitive":true,"description":"在服务商控制台查看"}

5.8 login_background：登录页背景

方法 login_background.get，参数固定为空对象 {}。插件只提供数据，不提供图片字节，也不负责布局。

{"id":"b1","method":"login_background.get","params":{}}
{"id":"b1","result":{
  "contentKind":"POSTER_FEED",
  "sourceName":"示例图库",
  "copyrightNotice":"示例图片署名",
  "items":[{
    "imageUrl":"https://images.example.com/poster.jpg",
    "title":"示例影片",
    "copyrightNotice":"© Example rights holder"
  }]
}}
contentKind条目数用途
POSTER_FEED0–40海报瀑布流
HERO_IMAGE恰好 1单张主视觉
SINGLE_POSTER恰好 1原比例完整呈现一张海报
SINGLE_IMAGE恰好 1原比例完整呈现带署名的单张图片
  • 响应 JSON 最大 256 KiB；最多 40 项；每个图片 URL 最长 2048 字节；sourceName 必填且 1–128 字符，title 最长 256，copyrightNotice 最长 512，文本不能为空或含控制字符。
  • 图片 URL 必须是 HTTPS、无凭据、无 fragment、无端口，主机与 permissions.imageHosts 中某一域名精确匹配。不要返回 localhost、本地域名或 IP 字面量；当前代码没有额外的本地/私网黑名单（见第 8 节），必须由插件自己保证。

  • 例外：只有 org.lux.login-background 声明了 image 配置字段时，才可返回固定路径 /api/v1/auth/login-background/custom-image；其它相对路径、查询参数或前缀匹配都不接受。

5.9 data_migration：Emby 迁移

必须声明 type: "data_migration"、category: "MIGRATION"、capabilities: ["migration.emby"]。宿主负责任务、映射、导入、幂等、恢复和历史事件；插件只负责与 Emby 通信并返回有界数据。

方法概要
migration.test验证 Emby 地址与 API key，返回脱敏服务器信息和 historyCapability；可返回 supportsFilteredReads
migration.list_users分页列出用户、库权限和头像标签；支持可选的用户/字段投影
migration.list_items按用户返回 Movie/Series/Season/Episode 的稳定 ID、ProviderIds、层级和可选用户状态
migration.user_state按 PLAYED、FAVORITE 或 RESUMABLE 筛选用户状态
migration.authenticate_user首次登录迁移账户时验证用户名/密码，只返回成功和脱敏身份
migration.person_favorites可选的演职人员收藏迁移；按 SDK 的分页/过滤规则实现

  "allowPrivateNetwork":false

插件不得返回或持久化 Emby access token、密码或完整认证响应；字段、分页、字段投影和错误处理细节见 SDK 的迁移章节。这里只给出方法族概要。

5.10 emby.route：Emby 兼容路由

emby.route 是附加能力。清单用 embyRoutes 声明精确方法和路径，宿主只把匹配的请求转发给已安装、启用且声明了该路由的插件。

{
  "type":"media_probe",
  "category":"MEDIA",
  "capabilities":["media.probe","emby.route"],
  "embyRoutes":[{
    "method":"POST",
    "path":"/Items/SyncMediaInfo",
    "rpcMethod":"emby.syncMediaInfo"
  }]
}

宿主调用的是 rpcMethod 指定的方法，请求参数形如：

{"id":"e1","method":"emby.syncMediaInfo","params":{
  "method":"POST",
  "path":"/Items/SyncMediaInfo",
  "query":"path=%2Fmedia%2Fmovie.strm",
  "headers":{"content-type":"application/json"},
  "bodyBase64":"e30=",
  "hostCapabilities":["media.info.import"]
}}
{"id":"e1","result":{
  "statusCode":200,
  "headers":{"content-type":"application/json"},
  "bodyBase64":"e30="
}}
  • 认证头、Cookie、完整 URL 和 Lux 内部身份不会传给插件；请求只含方法、路径、已脱敏的 query、已脱敏的非认证头和有界 Base64 body。
  • 同一清单最多 32 条路由，不能出现重复的 method + path；rpcMethod 是宿主实际调用的方法名。
  • 响应 statusCode 必须在 100–599；headers 最多 16 个，键/值长度受限；bodyBase64 解码后最大 256 KiB。
  • emby.route 的 RPC 超时只有 3 秒。可选的 mediaInfoImport Bundle（首个兼容路由 POST /Items/SyncMediaInfo）有额外的字段和大小校验，详见 SDK。

6. 环境变量与配置文件

宿主启动插件时设置以下环境变量（来源：plugin_runtime.rs）。插件的工作目录是插件包根目录。

变量何时提供说明
LUX_PLUGIN_ID总是插件 ID，与 manifest 的 id 相同
LUX_PLUGIN_PROTOCOL_VERSION总是manifest 的 apiVersion，当前为 1
LUX_PLUGIN_CONFIG_PATH仅 metadata 与 login_background本插件专属配置文件的绝对路径；这类插件不会收到 LUX_CONFIG_DIR
LUX_CONFIG_DIR其它类型（通知除外）旧兼容的共享配置目录；新插件不要依赖它。通知调用不暴露配置目录，凭据通过 RPC 的 secret 传入
LUX_PROXY_URL管理员配置网络代理时出站代理地址；被标记为绕过代理的插件不会收到，并且会把继承的代理变量移除
HTTP_PROXY、HTTPS_PROXY、ALL_PROXY可能从宿主环境继承插件不应假定一定存在；需要代理时优先读取 LUX_PROXY_URL。绕过代理的插件会同时移除这些变量及小写形式

6.1 配置文件格式

LUX_PLUGIN_CONFIG_PATH 指向一个 JSON 对象，键是 manifest 中 configFields 的 key。文件可能不存在（管理员尚未保存配置），插件必须使用自己的默认值，不能因此崩溃。

{
  "apiBaseUrl": "https://api.example.com",
  "apiKey": "saved-by-admin",
  "libraryIds": ["library-1"],
  "concurrency": 2,
  "mode": "fast"
}
  • 配置由管理员通过 Lux 管理页面修改，插件不应自行修改该文件。
  • 敏感字段也会写入这个文件。插件不能把内容打印到 stderr、写进错误消息或复制到其它位置。
  • 文件不存在、字段缺失或值类型不符合预期时，使用安全默认值；不要把“配置缺失”变成进程崩溃。
  • Lux 不会向插件提供数据库、媒体库路径、媒体文件列表、用户会话或内部 HTTP API 的地址/令牌。

7. 稳定错误码与使用规则

error.code 使用下列稳定值之一；类型合同另有专用错误码时（如媒体探测、评分查询），按对应合同使用。未知错误码可能被宿主当成失败处理，不要发明随意的字符串。

错误码使用场景
PLUGIN_INVALID_REQUEST请求参数缺失、类型不对、枚举越界或无法解析
PLUGIN_TIMEOUT上游请求超时；不要等宿主超时
PLUGIN_UNAVAILABLE上游不可用，或插件暂时无法服务
PLUGIN_RATE_LIMITED上游限流；如合同支持，可同时返回重试提示
PLUGIN_AUTH_FAILED上游鉴权失败；不得回显凭据、令牌或完整响应
PLUGIN_PROVIDER_NOT_FOUND未找到条目，或不支持该媒体类型/能力
PLUGIN_INVALID_RESPONSE宿主侧使用：插件输出无法解析、字段不合法或超限；插件通常不主动返回
PLUGIN_INTERNAL_ERROR插件内部错误，且没有更具体的分类

7.1 错误消息规则

  • message 只写简短、可诊断的说明，例如“上游超时”“缺少 apiKey”。不要拼接上游完整响应。
  • 不得包含凭据、API Key、访问令牌、Cookie、密码、完整 URL、完整查询串、用户数据或 stderr 内容。需要排查时只写主机名或错误类别，不写完整地址。
  • 不要把异常对象的原始字符串直接塞进 message；第三方库的异常经常带 URL 和请求头。
  • result 与 error 二选一；一个响应里不要同时出现。
  • 媒体探测使用 MEDIA_PROBE_INVALID_URL、MEDIA_PROBE_TIMEOUT、MEDIA_PROBE_PROCESS_FAILED、MEDIA_PROBE_INVALID_OUTPUT；评分查询使用 TRAKT_* 系列，详见 SDK。

8. 已知差异与容易踩坑的地方

以下是当前代码与 SDK 文档/开发指南文字不一致，或文档没有强调、但会直接影响安装和运行的地方。发生冲突时以代码为准；如果你在其它版本看到不同行为，以对应版本的源码为准。
项目文档说法当前代码实际行为
生命周期方法SDK 列出 plugin.hello、plugin.health、plugin.shutdown宿主不会发送这三个方法。插件按需启动；停止时直接终止进程，不会发送 plugin.shutdown。不要依赖它们做初始化或优雅退出。
apiVersion 类型SDK 的 manifest 示例写成字符串 "1"代码按无符号整数解析，必须写数字 1；字符串会让清单解析失败。
入口执行权限指南示例把入口放在 bin/plugin.py，并提示 chmod +xZIP 安装时只有 binaries/ 下的文件会被补成 0700。放在 bin/ 的脚本解压后通常没有执行权限，宿主直接执行会失败。请把入口放在 binaries/<platform>-<arch>/。
未知能力名指南称未知能力名会被拒绝代码只对未知的 danmaku.* 和 ratings.* 做拒绝；其它任意字符串可以通过清单校验，但宿主永远不会调用它。不要依赖这个宽松行为。
metadata.search 请求SDK/指南示例包含 providerId当前搜索请求只发送 itemType、name、year、language；providerId 出现在 metadata.get/images/credits/externalIds/trailers 等详情请求里。
章节标记枚举SDK 散文写作 IntroStart/IntroEnd/CreditsStart线上 JSON 使用 INTRO_START/INTRO_END/CREDITS_START（SCREAMING_SNAKE_CASE）。
stderr 日志指南说日志写 stderr运行时确实把 stderr 接走，但当前实现读到后直接丢弃，不写入 Lux 日志。stdout 仍然只能有协议响应；不要把 stderr 当作可查询的诊断通道。
metadata 分类指南称 category 必填且必须与类型匹配代码对 metadata 类型不校验 category，且省略时默认 SCRAPER。仍应显式写 SCRAPER，不要依赖默认值。
登录背景图片主机SDK 要求拒绝 localhost、本地域名和 IP 字面量validate_login_background_image_url 只检查 HTTPS、无凭据/端口/fragment，并要求主机与 imageHosts 精确匹配；没有独立的本地/私网黑名单。插件必须自己拒绝这些主机。
插件目录扫描时机商店安装与目录安装的说明不完全一致直接放进插件目录的包在启动时扫描；商店安装路径会重建目录并立即更新。手动替换/升级目录包后重启 Lux 最稳妥。

另外两点不属于“文档冲突”，但容易被误解：permissions.network 只是能力声明，不是宿主替你执行的出站白名单；password 字段也不会自动等于 sensitive，要隐藏配置值必须显式写 sensitive: true。

9. 发布到插件商店

Lux 不要求插件包使用 Lux 签名。发布流程是：构建每个架构的 ZIP → 计算 SHA-256 → 上传到你自己的 GitHub Release → 维护一个 HTTPS 可访问的 index.json → 管理员在 Lux 插件商店里添加该地址。Lux 只会下载目录中声明的 ZIP，并在安装前校验 SHA-256。

9.1 构建、打包、计算哈希

mkdir -p dist
cd org.example.ip-demo
zip -r ../dist/org.example.ip-demo-0.1.0-linux-x86_64.zip \
  manifest.json binaries/linux-x86_64
zip -r ../dist/org.example.ip-demo-0.1.0-linux-aarch64.zip \
  manifest.json binaries/linux-aarch64
cd ..
sha256sum dist/org.example.ip-demo-0.1.0-linux-x86_64.zip
sha256sum dist/org.example.ip-demo-0.1.0-linux-aarch64.zip

sha256sum 会输出“64 位十六进制哈希 + 两个空格 + 文件名”。把哈希原样填进 index.json 的 sha256 字段，不要填文件名或带 0x 前缀。示例输出形状：

<64 位小写十六进制>  dist/org.example.ip-demo-0.1.0-linux-x86_64.zip

在 GitHub 仓库创建 Release（例如标签 v0.1.0），把两个 ZIP 作为 Release 资产上传。资源 URL 应直接指向 ZIP 文件，使用 HTTPS，不要带凭据、查询参数或 fragment。

9.2 index.json 格式

目录格式版本为 1。每个插件声明 id、name、description、category、version、runtime、capabilities 和 packages；每个包声明 platform、arch、url、sha256。下面的哈希是占位值，不是真实构建产物：

{
  "formatVersion": 1,
  "plugins": [
    {
      "id": "org.example.ip-demo",
      "name": "示例 IP 归属地",
      "description": "演示用的最小 IP 归属地插件",
      "category": "NETWORK",
      "version": "0.1.0",
      "runtime": "process",
      "capabilities": ["ip.location"],
      "packages": [
        {
          "platform": "linux",
          "arch": "x86_64",
          "url": "https://github.com/example/lux-plugins/releases/download/v0.1.0/org.example.ip-demo-0.1.0-linux-x86_64.zip",
          "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
        },
        {
          "platform": "linux",
          "arch": "aarch64",
          "url": "https://github.com/example/lux-plugins/releases/download/v0.1.0/org.example.ip-demo-0.1.0-linux-aarch64.zip",
          "sha256": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb"
        }
      ]
    }
  ]
}
  • formatVersion 必须是 1；目录最多 100 个插件，索引文件最大 2 MiB。插件 ID 在同一个目录中必须唯一，version 非空且不能含 /。
  • runtime 是字符串 "process"，不是 manifest 里的对象。可选的 providerKey/aliases 仅 metadata 插件需要。
  • 每个 packages 项的 platform/arch 组合必须唯一；sha256 必须是 64 位十六进制，下载后会与实际文件比对。platform: "*"、arch: "*" 可作为兼容回退。
  • 包 URL 可以是绝对 HTTPS URL，也可以相对 index.json 的地址解析；解析结果仍必须是 HTTPS、无凭据、无 fragment。

9.3 让管理员添加目录

  1. 托管 index.json把文件放到 HTTPS 可访问的位置，或提交到你自己的 GitHub 仓库（GitHub 仓库地址可解析为 main/index.json）。
  2. 在 Lux 插件商店添加地址管理员最多可添加 10 个其它 HTTPS 目录；默认目录之外，Lux 会按插件 ID 合并并按最高 SemVer 去重。
  3. 安装并重启Lux 按当前平台选择 ZIP，校验大小、路径、manifest、平台入口和 SHA-256；商店安装会刷新目录，直接放目录的包则按第 8 节的启动扫描时机重启。
不要把 ZIP 直接提交进 Git 仓库或放进 index.json 的正文；用 Release 资产或静态文件托管。目录地址和包 URL 都必须是 HTTPS，且不要在 URL 中放令牌。

10. 发布前检查清单

  • ☐ formatVersion 与 apiVersion 都是数字 1；version 是三段纯数字。
  • ☐ id 只含允许字符、长度不超过 128，且不使用 org.lux.*。
  • ☐ type、category 与 capabilities 的组合符合第 3.2 节；chapter_detector 已声明 supportedMediaSourceKinds。
  • ☐ configFields 的 key 唯一；敏感字段标记 sensitive: true；通知插件只有 secret 是 password/sensitive 字段。
  • ☐ permissions.network 只列确实需要的主机；插件自身仍执行 SSRF/私网/保留地址检查。
  • ☐ entrypoint 是包内相对路径、不含 ..、实际存在，并位于 binaries/ 下以便获得执行位。
  • ☐ 入口对所有输入都返回一行 JSON 响应，不因异常退出；对非 JSON、缺字段、未知方法、空字符串都有错误响应。
  • ☐ stdout 只有协议 JSON；日志全部在 stderr；没有启动横幅或第三方库输出污染 stdout。
  • ☐ 错误码使用稳定值，错误消息不含凭据、令牌、完整 URL、查询串或 stderr。
  • ☐ ZIP 大小 ≤ 128 MiB、解压后 ≤ 256 MiB、文件数 ≤ 512、manifest ≤ 1 MiB；包里没有缓存和测试数据。
  • ☐ 在 linux-x86_64 与 linux-aarch64 上分别安装并测试通过。
  • ☐ index.json 的 sha256 与 sha256sum 输出一致，URL 是 HTTPS 且指向实际 Release 资产。
