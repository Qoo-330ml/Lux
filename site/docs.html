配置教程

从零开始，十几分钟把 Lux 跑起来并连上你常用的客户端。以下内容与仓库 README、docs/DEPLOYMENT.md 保持一致。

1. 部署

需要 Docker Engine 与 Docker Compose v2。新建一个目录，保存为 compose.yaml：

services:
  lux:
    image: pdzhou/lux:latest
    container_name: lux
    environment:
      LUX_SCAN_CONCURRENCY: ${LUX_SCAN_CONCURRENCY:-4}
      LUX_PROBE_CONCURRENCY: ${LUX_PROBE_CONCURRENCY:-8}
      LUX_FFMPEG_CONCURRENCY: ${LUX_FFMPEG_CONCURRENCY:-2}
    ports:
      - "8097:8097"
    volumes:
      - ./config:/config:rw
      - ./media:/media:rw
    restart: unless-stopped
docker compose up -d
宿主机容器用途
./config/config数据库、插件、配置和日志；必须持久化
./media/media媒体库；需要读写权限以支持 NFO 和图片写回
媒体在 NAS 的其他目录？把 ./media:/media 改成实际路径，例如 /volume1/video:/media。后面添加媒体库时填写的是容器内路径（如 /media/Movies）。

2. 首次初始化

  1. 打开 Web 首页浏览器访问 http://NAS地址:8097/，进入初始化引导。
  2. 选择数据库默认 SQLite（数据在 /config/lux.db），个人使用无需额外服务。要用 PostgreSQL 见第 7 节。
  3. 创建第一个管理员设置用户名和密码。
数据库后端只能在创建第一个管理员之前选择，已初始化的实例不支持在线切换。首次初始化建议只在局域网完成，不要把未初始化的 setup 页面暴露到公网。

3. 创建媒体库

  1. 进入管理控制台 → 媒体库点击新建媒体库。
  2. 选择类型电影、电视剧或混合。
  3. 添加根路径填写容器内路径，如 /media/Movies。一个媒体库可以添加多个根路径。
  4. 启动扫描扫描在后台任务中进行，可暂停、恢复、取消和重试；之后基于文件事件做增量更新。

推荐目录结构（NFO 与图片放在媒体旁，Lux 优先读取本地数据）：

/media/Movies/
  盗梦空间 (2010)/
    盗梦空间 (2010).mkv
    movie.nfo
    poster.jpg
/media/TV/
  某剧集 (2020)/
    Season 01/
      S01E01.mkv

4. 刮削与匹配

  1. 安装并配置刮削插件在管理控制台的插件库中安装 TMDb 等元数据插件。
  2. 处理待匹配条目低置信度的条目会进入候选匹配，手动确认即可；可锁定字段，避免被后续刮削覆盖。
  3. 管理图片海报、背景图等可在管理端调整，并原子写回到媒体目录。
刮削、NFO 解析和 ffprobe 都在后台任务里完成，不会占用你浏览和播放时的请求。

5. 连接客户端

Lux 提供 Emby 兼容接口，在支持 Emby 的第三方客户端里按“Emby 服务器”添加即可：

  1. 在客户端选择添加 Emby 服务器VidHub、SenPlayer、Infuse、Harbor、Hills、Yamby 等。
  2. 填写地址http://NAS地址:8097；使用反向代理则填写 HTTPS 域名。
  3. 填写 Lux 用户名和密码在“用户与权限”里可以为家人创建独立账号，并按媒体库设置访问权限。
Lux 以直放为主，不做转码、HLS 或字幕格式转换；能否播放某种编码、渲染某种字幕取决于客户端。各客户端的实测记录见 兼容性文档。

6. 远程访问

Nginx 反向代理

server {
    listen 443 ssl;
    server_name lux.example.com;

    ssl_certificate     /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8097;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_set_header Range $http_range;
        proxy_set_header If-Range $http_if_range;
        proxy_buffering off;
        proxy_request_buffering off;
        proxy_read_timeout 1h;
        proxy_send_timeout 1h;
    }
}

代理必须保留 206、Content-Range、Content-Length、Accept-Ranges 和 ETag，不要使用缓存整文件的代理模式。

Tailscale

用 Tailscale Serve 把 http://127.0.0.1:8097 映射到 tailnet 内部即可。除非额外配置了身份访问策略，否则不要使用公开的 Funnel。

不要把管理入口未经反向代理的安全措施直接暴露到公网。Docker 镜像目前以 root 运行，请保护好 /config。

7. 使用 PostgreSQL（可选）

在 Compose 中增加 postgres 服务：

  postgres:
    image: postgres:16-alpine
    container_name: lux-postgres
    environment:
      POSTGRES_DB: lux
      POSTGRES_USER: lux
      POSTGRES_PASSWORD: 请改成强密码
    volumes:
      - ./postgres-data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U $${POSTGRES_USER} -d $${POSTGRES_DB}"]
      interval: 10s
      timeout: 5s
      retries: 5
    restart: unless-stopped

首次引导里选择 PostgreSQL，主机填 postgres，端口填 5432，保存后点击页面上的“重启 Lux”。也可以填写环境中已有的 PostgreSQL。

8. 并发调优

在 Compose 同目录的 .env 中设置，修改后执行 docker compose up -d --force-recreate lux（单纯重启不会更新环境变量）：

变量含义范围 / 默认
LUX_SCAN_CONCURRENCY文件扫描并发上限1–1024 / 4
LUX_PROBE_CONCURRENCY媒体技术信息探测（ffprobe）并发1–512 / 8
LUX_FFMPEG_CONCURRENCY缩略图生成（ffmpeg）并发1–4 / 2
LUX_DB_MAX_CONNECTIONS数据库连接池大小1–100 / SQLite 8、PostgreSQL 20
需要限制硬件占用时，请同时调低前三个变量。实际并发还会根据 CPU、内存和存储延迟自动降级；SQLite 入库保持单写者，增加连接数不会突破这一限制。

9. 升级

docker compose pull
docker compose up -d

升级前建议备份 ./config 目录。回滚边界和版本固定方式见 部署文档。Lux 目前不内置备份恢复功能。

10. 常见问题

Web 端能直接播放吗？

暂不支持 Web 播放（浏览器解码能力有限），请使用第三方 Emby 客户端播放。

支持转码吗？

不支持。Lux 首版只做直放。

能和 Emby 同时用吗？

它们是两个独立服务，使用不同端口即可。注意 Lux 会向媒体目录写回 NFO 和图片，若 Emby 指向同一目录，请先确认两者的写回设置不会互相覆盖。

遇到问题怎么反馈？

到 GitHub Issues 提交，并附上客户端版本、平台、脱敏后的请求路径、状态码和关键响应字段。请不要贴出密码、令牌或完整的 .strm 地址。
