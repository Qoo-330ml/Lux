# Lux 用户管理设计方案

> 状态：按项目所有者 2026-10-19 指示分步实施；本文不代表相关功能已经实现或部署。原模块八“外挂字幕权限”已取消，不纳入实现范围。
> 日期：2026-10-19
> 适用范围：Lux Web 管理控制台、Lux API、Emby 兼容接口。
> 主规格：[LUX-DEVELOPMENT.md](LUX-DEVELOPMENT.md)。

## 1. 目标、现状与规格关系

目标是围绕七个实施模块，补齐账号生命周期、注册邀请、用户查询、权限复用、内容限制、播放控制、设备与活动管理。

### 1.1 已确认的产品选择

| 项目 | 选择 |
| --- | --- |
| 注册方式 | 默认邀请注册；管理员可开启公开邮箱注册 |
| 激活方式 | 邀请用户完成邮箱验证后直接激活；公开注册需要邮箱验证和管理员审批 |
| 角色预设 | 复制权限快照到用户；修改预设不自动改变已有用户 |
| 新用户媒体库 | 使用管理员指定的一组媒体库 |
| 偏好 | 保存到服务端，跨设备读取，支持选择项目复制 |
| 删除宽限期 | 默认 7 天，可配置 |
| 同时播放 | 新用户默认 2 路；已有用户迁移时不限；达到上限拒绝新播放 |
| 内外网权限 | 本轮不做按内外网阻止访问，也不做远程码率限制 |
| 内容分级 | 选择分级体系和最高允许等级 |
| 设备限制 | 默认全部允许，持续记录设备，采用黑名单 |
| 黑名单维度 | 设备、客户端、IP；不增加独立的操作系统规则维度 |
| 黑名单范围 | 同时支持全站规则和单用户规则，命中任意规则即拒绝 |

其余具体默认值见第 5 节；它们属于本方案的设计默认值。

### 1.2 当前实现基线

以下依据本地代码核对，不作为 FNOS 已部署版本的验收结果：

- 已有管理员创建、编辑、禁用、删除用户，以及最后一名有效管理员保护。
- 已有头像、媒体库访问权限、用户改密和部分账户设置。
- 管理员用户列表目前一次返回用户，尚需增加搜索、分页和状态筛选。
- 主题、首页分区、音轨与字幕语言等偏好目前主要保存在浏览器；部分播放设置和媒体库排序已保存在服务端。
- Web 登录会话与 Emby access token 分开存储，需要统一管理入口和撤销能力。
- 已有后台播放卡片与播放事件；当前播放记录以 90 秒活跃窗口判断，不等于已经具备原子的播放准入限制。
- 本地媒体已有直放、封装转换、音频转码和视频转码能力；STRM 沿用外部播放合同。
- 当前转发头用于 IP 展示和传输元数据，不用于来源 IP 的访问控制。

### 1.3 与现行规格的关系

本次只登记设计。后续每次实施一个 `LUX-*` 任务，并在修改行为前同步主规格、验收条件和相关规则。

| 现行规定 | 本方案的目标变化 | 实施前要求 |
| --- | --- | --- |
| 主规格 §3.10 不开放公开注册，后续账号由管理员创建 | 邀请注册，以及可选的邮箱注册与审批 | 在注册专项任务中更新条文，明确开关、激活和审批流程 |
| 旧版媒体库授权表中没有正向记录代表可访问全部 | 显式区分全部、指定、无权限 | LUX-627 登记模式字段及迁移；LUX-628 接入读取与兼容写入；后续任务接入管理选择器和新用户默认权限 |
| 内容分级、标签限制属于后续阶段 | 本专项纳入统一内容访问检查 | 登记对应任务及所有读取、播放入口的验收矩阵 |
| `AGENTS.md` 与既有反代合同不允许将展示用转发头用于 ACL | IP 黑名单通过可信代理来源和独立解析规则确定封禁依据 | 在 IP 黑名单任务中明确修订规则；不直接复用展示 IP 作为 ACL |

Rust、React + TypeScript、单进程服务、有界后台工作以及 Lux/Emby DTO 分离继续遵守现有架构。SQLite 与 PostgreSQL 均需要迁移和验收。

## 2. 页面结构与七个实施模块

### 2.1 整体页面结构

- **用户列表**：搜索筛选、创建用户、审批注册、创建邀请、批量操作；提供已删除用户入口。
- **用户详情**：分为资料、权限、偏好、设备与登录、播放与活动等标签，避免在列表内展开全部配置。
- **全局设置**：注册方式、邮件、新用户默认权限、角色预设、全站黑名单、删除宽限期、活动保留期和可信代理。
- 普通配置编辑后统一保存；删除、恢复、撤销登录、停止播放等操作独立执行并展示结果。
- 用户自己的账户页沿用现有入口，补齐邮箱验证、服务端偏好和个人登录设备查看。

### 2.2 模块一：账号资料与生命周期

#### 资料

- 用户名用于登录，显示名称用于界面展示；保存头像、邮箱和邮箱验证状态。
- 用户可修改自己的显示名称、头像和邮箱；修改邮箱需要重新验证。
- 管理员从用户详情维护资料和账号状态；邮箱变更不得自动标记为已验证。
- 保留现有密码修改和重设入口、身份校验与 CSRF 保护。

#### 状态与删除

- **待激活**：通过附加原因区分等待邮箱验证、等待管理员审批；不能访问媒体。
- **正常**：按照已分配权限使用服务。
- **禁用**：禁止登录和继续访问，保留用户数据。
- **已删除**：作为回收站状态呈现，通过删除时间和计划清理时间管理，不与普通启用/禁用混用。
- 禁用或删除立即撤销登录、失效相关播放授权并停止服务端控制的播放。
- 删除后默认保留 7 天；宽限期内恢复原有资料和权限，登录凭证不恢复，需要重新登录。
- 宽限期结束后清理账号、头像、偏好、播放进度、收藏和设备关联，不删除媒体文件；审计记录沿用既有保留策略。
- 回收站提供恢复和提前彻底删除入口，明确展示影响范围。
- 最后一名有效管理员不得被禁用、删除或通过权限调整失去管理能力。

### 2.3 模块二：注册与邀请

#### 邀请注册

- 默认使用邀请注册，保留管理员直接创建用户的入口。
- 管理员填写指定邮箱、权限预设和可访问媒体库，生成邀请；支持邮件发送和复制链接。
- 邀请默认绑定指定邮箱、单次使用、7 天有效，支持撤销、重新发送及状态查询。
- 邀请携带创建时确定的权限与媒体库快照，避免预设后续变动导致受邀权限变化。
- 受邀用户完成邮箱验证、设置用户名和密码后直接激活，无需再次审批。

#### 公开邮箱注册

- 管理员可开启公开邮箱注册，默认关闭。
- 流程：提交注册 → 验证邮箱 → 等待管理员审批 → 激活。
- 审批页展示申请时间、邮箱验证状态和拟分配权限；管理员可以调整权限后批准。
- 新用户从默认权限取得快照；待激活期间不取得媒体访问能力。

#### 邮件与凭证

- 全局配置 SMTP、发件人和站点访问地址；提供发送结果及失败重试入口。
- 邮件通过有界后台队列发送，持久化发送状态，限制重试次数；发送失败不误标激活成功。
- 验证凭证有有效期、单次使用；凭证只保存校验摘要，密码和原始凭证不进入日志。
- 注册、验证和重发邮件需限制请求频率；重复提交不得创建重复账号或重复消费邀请。

### 2.4 模块三：用户列表与查询

#### 展示与查询

- 列表显示头像、用户名、显示名称、邮箱、状态、预设来源、最近登录、最近活跃和当前播放数。
- 按用户名、显示名称、邮箱搜索；按账号状态筛选；提供待审批和已删除用户入口。
- 支持按创建时间、最近登录、最近活跃排序。
- 默认每页 20 条，服务端每页最多 100 条；在服务端先筛选和排序，再分页并返回匹配总数。
- 最近登录指成功认证时间；最近活跃覆盖 Web 和 Emby 的有效用户操作，不仅从登录凭证创建时间推算。

#### 批量操作

- 支持批量启用、禁用、调整权限、应用预设和复制偏好。
- 操作前显示用户数量、目标用户和变更摘要；明确选择当前页还是全部筛选结果。
- 执行时只修改勾选的配置组，完成后逐项报告成功、失败和原因。
- 服务端再次校验权限、目标范围及最后管理员保护，不依赖前端按钮限制。

### 2.5 模块四：权限预设与批量管理

#### 新用户默认权限

- 管理员配置默认媒体库、播放、下载和转码权限；不设置用户级字幕权限。
- 媒体库权限采用显式模式：**全部媒体库 / 指定媒体库 / 无媒体库权限**。
- 新用户使用管理员指定的一组媒体库；指定项清空后表示无权限，不自动开放全部。
- 新增媒体库只有在“全部媒体库”模式下自动可见；指定模式保持原选择。

#### 角色预设

- 提供管理员、普通用户基础预设，允许创建和维护自定义预设。
- 应用预设时复制权限快照；保留来源信息供查询，但不建立自动继承。
- 修改预设不改变已有用户；通过批量应用更新已有用户，并选择覆盖的权限组。
- 进入管理控制台的权限单独展示，避免复制普通播放配置时意外授予管理权。

#### 权限与偏好复制

| 类型 | 可选复制内容 |
| --- | --- |
| 权限 | 媒体库、内容限制、播放、下载和转码 |
| 偏好 | 主题、强调色、首页分区、媒体库排序、音轨与字幕语言、自动连播、播放完成比例 |

- 提供一个来源用户、多个目标用户及配置项目选择，先预览再应用。
- 身份资料、密码、登录凭证、观看历史和收藏不属于复制范围；设备记录和黑名单使用各自管理入口。
- 复制后的媒体库排序过滤目标用户无权访问的媒体库，并继续遵守管理员强制排序策略。
- 账户偏好统一保存到服务端；浏览器本地数据仅作为缓存及首次迁移来源。
- 旧浏览器设置只在服务端尚无对应设置时导入，不能覆盖更新的服务端配置。
- 保存和批量复制需要版本检查，防止旧页面无提示覆盖新设置。

### 2.6 模块五：内容访问限制

#### 配置项

- 分级体系、最高允许等级；不把 TMDb 等数值评分当作年龄分级。
- 未分级内容允许或禁止；缺失、无法识别或无法映射到所选体系的值按未分级处理。
- 允许标签、禁止标签。

#### 判定规则

可访问内容必须同时满足：**媒体库权限 + 分级限制 + 标签限制**。

- 配置允许标签后，内容至少命中一个允许标签；未配置时不增加标签允许条件。
- 命中禁止标签即拒绝，禁止规则优先，不能用允许标签绕过分级或媒体库权限。
- 剧集、季度和单集遵守上级限制，不能通过直接访问下级条目绕过受限父级。
- 首页、搜索、合集、详情、图片、字幕、下载和播放执行统一检查。
- 列表在分页之前过滤，匹配总数、推荐缓存和可见内容保持一致。
- 分级与标签在扫描、元数据更新等后台流程中建立索引；已有内容通过有界后台任务回填。
- 用户请求不读取整库 NFO，不进行全库扫描；开启限制时需要明确展示索引就绪状态，未就绪内容不得绕过限制。

### 2.7 模块六：播放与转码权限

#### 配置项

- 是否允许播放；与是否允许浏览、下载分别配置。
- 同时播放上限：新用户默认 2 路，`0` 表示不限；已有用户迁移时不限。
- 分别允许封装转换、音频转码、视频转码，并与服务器可用能力取交集。
- 本轮不做按内外网阻止访问，也不做远程码率限制；旧兼容字段不能继续作为无实际效果的管理开关展示。

#### 播放准入与计数

- Web、Emby、本地媒体与 STRM 共用用户播放额度，复用现有播放记录和后台播放卡片。
- 达到上限拒绝新播放，不抢占已有播放，并明确提示用户当前播放数和上限。
- 发放播放链接时检查额度，在实际播放准入处原子占位；单纯读取播放卡片数量不足以处理并发竞争。
- 被动媒体信息协商不占额度、不终止已有播放；真正启用媒体链接时再次检查并准入。
- 同一播放会话的刷新、拖动、Range 请求、HLS 分片和重复回调复用原有名额，停止、失败或失效后正确释放。
- 暂停但持续上报的会话仍占名额；无上报会话沿用当前 90 秒活跃判定回收，并覆盖客户端漏报停止的情况。
- 额度降低到当前播放数以下时保留已有会话，阻止继续新增，直到回落到限制内。
- 用户播放额度与服务器 FFmpeg 并发额度分别计算，新增用户权限不得绕过服务器资源限制。

#### STRM 边界

STRM 继续使用现有外部直放、解析和短期票据流程，不增加视频转码或字节代理。Lux 可以拒绝新的授权、后续取链和票据续用；已经交给外部播放器的目标链接，无法保证立即中断。界面与验收需要如实区分这两类结果。

### 2.8 模块七：设备、会话与活动记录

#### 设备记录与黑名单

- 默认允许全部设备，持续记录成功登录和有效访问所关联的设备。
- 展示设备名称、设备标识、客户端、版本、首次出现、最近活跃、IP、归属地及登录状态。
- 设备与客户端信息来自客户端声明，用于日常账号管理；不能把它当作不可伪造的硬件身份。

| 黑名单维度 | 配置方式 |
| --- | --- |
| 设备 | 从设备记录中选择具体设备 |
| 客户端 | 从已记录的客户端名称中选择，按规范化名称匹配 |
| IP | 指定 IPv4、IPv6 或 CIDR 网段 |

- 规则支持全站和单用户两种作用范围；命中任意黑名单即拒绝，不设置相互覆盖的放行例外。
- 不增加单独的操作系统维度。
- 新增规则需要影响已有登录和播放授权，并记录命中原因；解除规则后，已撤销的登录不会自动恢复。
- 规则保存前检查当前管理员会话，拒绝直接封禁当前管理入口的变更；继续遵守最后管理员保护。

#### Lucky 与 IP 来源

项目所有者提供的 FNOS 部署信息：Lux 通过 Lucky 反向代理访问；Lucky 已开启“追加客户端 IP 到指定 Header”，自定义 Header Key 为 `X-Forwarded-For`，当前 Lux 可以显示实际用户 IP。

这说明真实 IP 的传递链路已配置。它不等于已经验证过异常请求和封禁行为，也不作为本次对线上环境的现场核验结果。

IP 封禁设计收敛为一项全站高级配置：**可信代理地址或网段**。默认 Header 沿用 `X-Forwarded-For`，无需为每条黑名单重复配置。

- 直连 Lux 时使用网络连接来源 IP。
- 只有直接连接 Lux 的来源属于配置的可信代理时，转发链才参与封禁依据计算；否则忽略该头用于 ACL。
- 按完整代理链从靠近 Lux 的一侧逐跳校验，处理多值及重复 Header，不能无条件取最左侧 IP。
- 保留展示 IP 与封禁依据的区分；配置页展示当前请求的连接来源，便于识别 Lucky 在 Lux 看来的地址。
- 实施前核对 Lucky 当前版本是否覆盖或保留访问者自带的同名 Header；仅凭“追加”这一界面名称不推断实际行为。
- 现有 IP 展示与 HTTPS 元数据合同不因登记本文而改变；IP 黑名单实施前同步修订主规格和 `AGENTS.md` 的相关规则。

有关转发链和安全用途的依据见 [MDN：选择 X-Forwarded-For 地址](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-Forwarded-For#selecting_an_ip_address)；Lucky 功能说明见 [Lucky Web 服务文档](https://lucky666.cn/docs/modules/web/)。

#### 登录与播放管理

- 统一展示 Web 登录会话与 Emby 登录凭证的管理摘要，支持撤销单次登录或该用户全部登录。
- 原始 Cookie、token 和密码不返回管理界面，不进入活动日志。
- 撤销登录同时使其关联的播放授权失效；单独停止播放保留账号登录。
- 查看当前播放时复用现有后台卡片，支持停止服务端会话，并如实展示 STRM 的控制边界。

#### 活动记录

- 展示最近登录、最近活跃、登录失败、历史播放和关联设备。
- 支持按用户、事件类型、时间筛选与分页；新增活动索引默认保留 90 天，保留期可配置。
- 沿用现有日志与审计机制，增加适合用户查询的有界索引，不在每个用户请求中反复扫描全部归档。
- 活动保留期不清理观看进度、已看状态和收藏；登录失败记录不得包含密码、凭证或完整外部 URL。

### 原模块八：外挂字幕权限（已取消）

本模块不实施用户级字幕下载/管理权限，也不新增字幕文件上传、替换或删除能力。现有字幕播放读取、管理员修改字幕元数据属性、字幕索引与扫描继续按 Lux 既有规格运行；这次范围调整不移除或改变这些现有功能。内容访问限制仍按模块五统一约束媒体内容访问，包括已有的字幕读取路径。

## 3. 服务、数据与接口设计

### 3.1 服务边界

- 建立统一用户策略服务，供 Lux API、Emby API、播放、下载和图片入口调用。
- HTTP handler 负责解析、校验与 DTO 映射；策略与生命周期放在 application/auth，SQL 保持在 storage。
- Lux 与 Emby 路由和 DTO 分离，共用领域权限与业务服务，避免两条协议执行不同限制。
- 对权限、状态、黑名单和会话撤销建立失效机制，使已有登录和缓存及时遵守新策略。
- 邮件发送、到期删除、活动过期清理和内容策略索引回填使用有界后台工作。

### 3.2 数据能力

### 3.4 迁移原则

- 已有用户保留资料、当前可访问媒体库和实际播放能力；并发上限迁移为不限。
- 旧版空媒体库选择显式迁移为“全部”，非空选择迁移为“指定”，不误转成无权限。
- 原有禁用状态继续有效；邮箱缺失不导致已有账号突然进入待激活。
- 旧浏览器偏好仅在服务端缺少对应设置时导入，不用默认值覆盖已有服务端设置。
- 不伪造无法从旧数据可靠恢复的设备、失败登录或历史活动；界面允许显示未知和记录起始时间。
- 数据库变化同时提供 SQLite、PostgreSQL 迁移，覆盖从空库启动和从现有数据库升级。
