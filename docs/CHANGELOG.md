# Lux 更新日志

Lux 的版本变更记录，从 `0.1.0` 开始按版本倒序排列。

> 说明：仓库当前没有 Git tag。本日志根据源码版本 bump 提交和仓库初始提交整理；日期是对应提交日期，不等同于已发布到各渠道的正式发布日期。每个版本只记录主要的用户可见变化，不逐条复制 Git 提交。

## [0.3.1] - 2026-08-28

### Added

- 增加 LuxPlayer 控制器、播放引擎与运行时边界，在保留既有原生、HLS 与客户端回退链路的前提下统一播放器状态和会话控制。
- 增加播放器指针手势与平台适配：单击播放/暂停、双击全屏、拖动进度和音量，并适配桌面、触控及窄屏布局。
- 增加播放器诊断、设置面板、顶部栏和模块化控制组件，便于后续独立演进而不改变播放协议。
- 增加当前媒体源的字幕选择、原生 WebVTT 与 Lux 文本字幕叠层，并支持安全的字幕偏移控制。
- 增加受限的 Lux 弹幕读取、调度和显示开关，以及循环播放、画面比例、镜像、AirPlay、隐藏进度条和章节时间轴控制。

### Fixed

- 修复播放会话切换时并发启动、停止和状态回写可能相互交错的问题，改为按顺序处理会话过渡。
- 修复播放页控制栏在启动时的视觉闪烁、响应式布局和媒体详情入口的播放器交互问题。
- 修复字幕未随已选媒体源切换、弹幕与播放器控件重叠，以及播放回退和会话释放时的生命周期边界问题。
- 修复媒体库在后台扫描或 STRM 探测运行时无法删除的问题；删除会请求取消相关任务且不会修改媒体文件，管理台会显示失败原因并即时移除已删除卡片。
- 修复部分 Emby Android 客户端丢失播放鉴权头，以及 Yamby 使用季 ID 请求剧集分集时无法返回正确分集的问题。

### Changed

- Lux Web 播放页改用模块化 LuxPlayer 呈现层；既有播放能力、鉴权、媒体访问控制和服务端会话接口保持兼容。
- 控制层视觉样式按第三方播放器公开示例的交互密度进行独立实现；不引入其运行时依赖、不复制其代码或品牌资源。
- Lux 章节、字幕和弹幕均按当前媒体源读取；章节时间轴可标示片头、片尾并提供跳过片头入口。

## [0.3.0] - 2026-08-27

### Added

- 增加供应商无关的 metadata 插件兼容层，支持稳定的 `providerKey`、`aliases`、通用 RPC 和透明的 provider ID。
- 增加 metadata 插件专属配置路径与旧版 TMDb 配置的一次性兼容迁移，降低插件对服务器其他配置和凭据的可见范围。
- 增加首页和媒体库查询的批量读取路径，减少大媒体库场景下的重复数据库查询。
- 增加元数据资源写回策略，生成的 NFO 和图片默认写入媒体目录旁车，并支持按全局或媒体库策略额外镜像到 metadata 目录。

### Fixed

- 修复 Emby 迁移为每个用户遍历完整媒体库的问题；现在只读取已看、收藏和可继续播放的媒体，并在宿主侧去重后匹配，降低大媒体库迁移耗时。
- 修复 Emby 迁移遗漏用户权限的问题；现在同步远程访问、内容下载和可唯一映射的媒体库权限，同时保留 Emby 管理员不自动提升为 Lux 管理员的安全边界。
- 修复旧版 metadata 配置迁移重复执行或覆盖已有插件配置的问题，并保留旧配置文件以便回滚。
- 修复目录和首页缓存刷新事件持续重置防抖窗口、导致缓存刷新可能长期饥饿的问题。
- 修复内嵌插件目录中的 TMDb、豆瓣包校验值与实际发布包不一致的问题。
- 修复 Emby 迁移重复遍历完整媒体库和遗漏用户权限的问题；现在只处理有状态条目，并同步可安全映射的远程访问、下载及媒体库权限。
- 修复备用与补充刮削器的能力回退、列表合并、演员字段补全和背景图重复写入问题，并保留已经确认的主来源身份。
- 修复 Web 启动时浏览器标题闪烁及不同图片类型编辑器使用错误宽高比的问题。

### Changed

- TMDb、豆瓣的上游 HTTP 客户端、DTO、认证和图片处理从 Lux 主程序移至独立插件；主程序不再编译或创建内置 TMDb provider。
- metadata 插件配置改由 manifest 字段和插件专属文件管理，具体 provider 的健康状态与配置由插件负责；主程序健康检查和网络诊断不再硬编码 TMDb。
- 自动生成的媒体库封面默认调整为 1280×720，并同步优化标题与副标题的排版比例。
- metadata 资源使用 Emby 兼容的旁车命名，背景图按来源 URL 去重并依次写入 `backdrop.jpg`、`backdrop1.jpg` 等文件；旧版 `fanart` 命名继续兼容读取。
- 有序刮削器改为主来源按能力逐项由备用来源接管，身份确认后由补充来源只填充缺失字段、合并多值内容和背景图，不覆盖本地或已确认结果。

## [0.2.9] - 2026-08-27

### Added

- 增加 Emby 迁移对无效媒体记录的可追踪跳过报告，保留来源用户、分页位置和条目类型等诊断信息。
- 增加 Web 本地媒体播放会话，支持签名 Direct 播放、0～4 档播放计划、服务端 fMP4/CMAF HLS，以及播放事件、心跳和停止控制。
- 增加受限的服务端 HLS 运行时，使用 Jellyfin FFmpeg 7 处理本地媒体，并提供会话级临时资源、并发限制和生命周期回收。
- 增加 Redia/Emby 标准媒体源兼容支持，提供标准视频播放地址，并允许通过媒体源 ID 查询所属可见条目。
- 增加元数据补全资源管线，按缺失字段和图片类型生成最小请求计划，并记录阶段耗时、缓存命中、重试和图片字节等脱敏指标。

### Fixed

- 修复 Emby 迁移插件返回单条无效媒体记录导致整页无法解析、迁移提前中断的问题；现在会定位并跳过该条记录，继续处理后续页面。
- 修复迁移返回的用户和媒体名称包含控制字符时污染报告或界面显示的问题，名称会在不修改 Emby 源数据的前提下规范化。
- 修复 Web 播放会话停止、超时、页面关闭和服务重启后的 HLS 进程及临时目录未及时回收的问题。
- 修复 `.strm` 播放进入服务端 HLS 或转码路径的问题；直连失败时明确返回不支持，不创建 FFmpeg 进程或代理媒体字节。
- 修复首页精选媒体播放仍先进入详情页，以及剧集详情在单集加载期间点击播放后无法继续跳转的问题。
- 修复本地绝对路径型 `.strm` 目标位于媒体库根目录之外时无法播放的问题。
- 修复 Redia 使用媒体源 ID 请求条目或播放地址时无法解析的问题，并保留旧版媒体源路径入口的兼容行为。
- 修复元数据补全重复请求无关刮削能力、重复下载明确无图片资源，以及永久失败状态被反复重试的问题。
- 修复图片临时失败的指数退避、成功后的重置和元数据锁定字段处理，避免失败图片影响已成功写入的元数据。

### Changed

- Emby 迁移仅对可恢复的无效响应执行分页二分恢复；网络、认证、插件进程和数据库错误仍会暂停任务并保留失败阶段。
- Web 播放按浏览器能力、媒体轨道和管理员资源策略优先选择 Direct、客户端 fallback 或服务端 HLS；服务端会话使用短期签名 URL，并受进程组、磁盘和并发配额约束。
- 运行时统一使用固定版本的 Jellyfin `jellyfin-ffmpeg`，不再安装普通 Debian FFmpeg；`.strm` 始终只允许档位 0。
- 本地 `.strm` 播放仅校验源文件位于媒体库根目录内，并将目标 canonicalize 为存在的普通文件；允许目标位于根目录外但不访问远程目标、不修改 `.strm` 内容，也不开放目录或 `.strm` 文件作为媒体。
- Emby 兼容层的媒体源播放地址统一使用 `/Videos/{ItemId}/stream[.Container]?MediaSourceId={MediaSourceId}`，`GET /Items/{MediaSourceId}` 可回退解析到所属条目；路径型 `.strm` 继续按 `Protocol=File`、`IsRemote=false` 返回，Lux 不访问或代理云盘媒体。
- 元数据、图片下载、图片写入和人物补全使用独立的有界资源配额；SQLite 默认 4 路、PostgreSQL 默认 8 路，进程硬上限为 16 路，并按前台、CPU 和内存压力动态降档。
- 元数据候选、刮削器能力和 provider 缓存支持复用及 singleflight，演员详情移出主元数据 worker，降低后台补全对前台请求和数据库写入的争用。

## [0.2.8] - 2026-08-25

### Added

- 增加独立弹幕匹配插件 `org.lux.danmaku`，支持管理员配置弹幕 API，并为媒体库创建异步匹配任务、查询任务详情、取消和重试。
- 增加通用 `.strm` 目标解析器插件能力，支持 SMB/FTP 目标安全解析为 HTTP(S) 播放地址，并保持不支持目标不生成直链。
- 增加统一后台任务运行历史，集中展示和管理 STRM 探测、片头片尾检测、弹幕匹配和媒体库封面生成任务。
- 增加可恢复的人物索引重建任务，支持进度查询、取消、重启恢复和按媒体库范围管理。
- 增加有界的元数据后台任务调度与任务范围记录，支持进度合并、跨媒体库任务互斥和失败任务安全重试。
- 在 Emby 迁移助手插件配置页提供完整的 Emby → Lux 工作区，支持连接测试、预览迁移、正式迁移、用户/媒体匹配结果和历史报告查看；不再提供独立的 Emby 迁移控制台入口。
- 增加 Emby 迁移插件边界与宿主任务服务，支持用户资料、收藏、已看状态、播放进度、播放次数和最近播放时间导入。
- Emby 迁移增加用户级演员/人物收藏导入，支持 Provider ID 和规范化姓名匹配，并在插件配置页展示人物收藏报告。
- Emby 迁移助手插件设置支持统一保存 Emby 地址、API Key 和局域网访问权限，迁移页面可直接读取已配置来源。
- 增加 Emby `DisplayPreferences` 兼容接口，支持 Infuse 等客户端在登录后读取显示偏好。
- 增加用户级人物收藏功能，支持在人物详情页收藏或取消收藏人物，并在 Emby 人物数据中返回当前用户的收藏状态。
- 增加人物搜索和影视作品列表，支持从搜索页查找人物并查看其参演电影、剧集和季度作品。
- 增加弹幕匹配插件配置项，支持选择媒体库、标题匹配方式、并发数和是否覆盖已有弹幕文件。
- 建立与具体供应商解耦的元数据刮削器适配边界，统一支持 TMDb 和外部刮削器插件的搜索、详情、图片、演职员及预告片能力。
- 增加媒体库有序刮削器配置，支持设置主刮削器以及补充、备用或兼具两种角色的后续刮削器，并在管理 API 和页面中持久化排序。
- 增加持久化扫描变更目标和后处理阶段，记录新增、修改、删除及旁车变化，支持按变更集处理并在任务恢复后继续执行。

### Fixed

- 修复管理台操作页遗漏章节检测、弹幕匹配和 STRM 探测任务状态及操作入口的问题。
- 修复 `.strm` 的 SMB、FTP、本地路径和不支持协议目标在扫描、探测或播放时被错误当作 HTTP 直链的问题。
- 修复批量扫描准备和媒体库写入阶段的处理效率问题，降低大批量电影扫描的额外开销。
- 修复 SQLite 重建后人物索引丢失、过期人物出演记录残留和重复触发重建的问题。
- 修复刮削器插件和图片下载遇到临时进程故障时无法自动重试的问题。
- 修复插件版本比较将降级误判为更新，以及更新校验完成前提前停止旧插件的问题。
- 修复 AfuseKt 等 Emby 客户端登录请求的认证头兼容问题。
- 修复迁移播放进度选择较旧状态，以及媒体库计划任务默认值不安全的问题。
- 修复删除媒体库后 STRM media-info 插件仍保留失效媒体库 ID 和计划任务的问题。
- 修复人物关系快照无法唯一匹配媒体源时被静默跳过的问题，改为隔离保存并在媒体源恢复后自动重试。
- 修复插件更新时旧包与新包同时存在导致仍选择旧插件的问题，更新校验后优先加载目标版本。
- 修复人物 credit 重建时重复关系记录被重复索引的问题。
- 修复 Emby 迁移遇到无效媒体分页时提前终止后续用户或媒体处理的问题。
- 修复弹幕插件配置保留已删除媒体库，以及人物搜索返回不可用演员的问题。
- 修复使用指定刮削器时错误读取其他供应商 ID、候选能力边界未生效及直接 ID 匹配兼容性问题。
- 修复多刮削器补充元数据时覆盖本地 NFO、锁定字段或更高优先级来源的问题。
- 修复媒体库有序刮削器管理控件在窄布局中换行、操作按钮错位和清除按钮文字显示不完整的问题。
- 修复扫描时媒体旁车变化未被识别、失败搜索请求未唤醒后续请求，以及移动端任务详情和注册任务操作按钮布局异常的问题。
- 修复自动元数据匹配和候选写入中重复候选被重复处理或重复落库的问题，并使候选写入保持幂等。
- 修复人物 manifest 未变化时反复进入重建队列，并将旧人物目录迁移状态与 manifest 恢复状态分离，避免迁移重复执行。
- 修复管理台筛选“已完成，有问题”或“延后”元数据任务时误请求不支持该状态的任务接口的问题。
- 修复注册任务 Cron 编辑器帮助文本与保存、取消控件的对齐和布局问题。

### Changed

- STRM 截图兜底不再依赖在线刮削匹配：无刮削器、无候选或缺少主图时均可生成截图，并将同一文件同时作为 `POSTER` 与 `THUMB` 提供给客户端。
- 弹幕配置迁移到独立插件配置，匹配工作由受监督插件执行；宿主负责任务队列、并发、取消、重试和旁车结果登记。
- 完善 `.strm` 目标分类和播放策略：HTTP(S) 保持原有直连，本地路径使用受保护的 Lux 端点，SMB/FTP 交由已启用的解析器处理，Lux 不代理媒体字节。
- 统一计划任务和一次性后台任务的运行记录、状态、进度与错误摘要，管理台可按任务类型查看历史并执行控制操作。
- 人物索引改用 keyset 分页、内容指纹跳过和专用查询索引，减少大媒体库重建与人物详情查询的重复扫描。
- 元数据任务摘要先分页聚合，后台 worker 数量和进度事件均受边界控制，服务重启后遗留任务可继续处理。
- 插件更新严格按 SemVer 判断，仅在新包验证并原子替换成功后停止旧进程，保留启用状态与配置。
- Emby 迁移采用只读源、幂等后台任务和 `DRY_RUN`/合并策略，API Key 与用户密码仅在受控迁移流程中使用，不写入日志或普通响应。
- 仪表盘资源指标统一按容器 cgroup 和 `/media` 文件系统统计，明确区分指标来源与不可用状态。
- Emby 迁移工作区收拢到插件配置页，不再提供独立迁移控制台入口；连接测试和迁移任务统一使用插件配置，并保留迁移任务的受控密钥引用。
- 人物关系恢复增加隔离区和后续重试流程，避免不匹配快照污染人物索引，同时保留可恢复的原始关系数据。
- Emby 迁移报告增加人物收藏结果分页和类型化展示，避免不同报告记录混用导致管理页显示错误。
- 调整 STRM 播放策略：远程 HTTP(S) 目标先由 Lux 播放入口使用播放器 User-Agent 解析有限重定向，再把最终地址以 307 返回给媒体客户端；本地路径仍通过受保护的 Lux 端点，解析器目标继续交由对应插件处理，Lux 不代理媒体字节。
- Emby 迁移报告使用可读的 Lux 媒体名称，人物作品列表按规范人物身份聚合并支持分页。
- 元数据应用层统一通过供应商无关的刮削器边界访问 provider key 和命名空间，TMDb 特有端点模型收敛在适配器内，便于扩展其他刮削器。
- 元数据任务按媒体库配置顺序先使用主/备用刮削器确认身份，再由补充刮削器填充缺失字段和图片；旧的单值 `scraperId` 配置继续作为首位兼容镜像。
- 扫描将文件发现、索引调和与后处理阶段分离，未变化文件跳过重复索引修复、指纹和 ffprobe；后处理并发受资源配额约束，前台请求不被扫描阻塞。
- 提升扫描与媒体探测吞吐：ffprobe 默认并发提高至 256、全局硬上限为 512，并行化有界指纹 I/O，同时完善资源观测和性能基准记录。
