# Lux 更新日志

Lux 的版本变更记录，从 `0.1.0` 开始按版本倒序排列。

> 说明：本日志根据源码版本、Git 提交和已记录的验证结果整理；日期是对应提交日期，不等同于已发布到各渠道的正式发布日期。每个版本只记录主要的用户可见变化，不逐条复制 Git 提交。
>
> 发版时两处都要改：本文档，以及应用内「设置 → 更新日志」页面使用的内置列表：新版本条目追加到 `web/src/features/admin/changelog/releases/` 下对应大版本的文件（如 `v0-7.ts`）；新大版本需新增文件，并在 `releases/index.ts` 中按倒序插入（该页面不读取本文件）。

## [Unreleased]

### 新增

- **媒体库菜单的“刷新元数据”按当前刮削模式显示并执行**：后台媒体库卡片的操作菜单里，该项文字随媒体库
  生效的“元数据刮削模式”变化——模式为“完整刮削”时显示“全量刷新元数据”（重新获取并覆盖未锁定的元数据和
  图片），为“仅补全”时显示“补全缺失元数据”（只补缺失项）；鼠标悬停提示同步说明。生效模式的取值顺序不变：
  媒体库自己的策略优先，没有则用全局策略，都没有则为仅补全。只改 Web 菜单文字，不新增弹框，也不改后端
  接口和已有行为。
- **Emby 详情页的“相似推荐”返回真实数据**：Hills 与 Yamby 每次进入电影/剧集详情都会请求
  `GET /emby/Items/{id}/Similar`，Lux 此前返回 404 空响应，推荐区整块缺失（页面不报错）。现在根路径与
  `/emby` 前缀都提供该端点，返回 `Items`/`TotalRecordCount`：只包含同类型且至少共享一个 Genre 的条目，
  共享数量多的排前面，再按标题和 id 稳定排序；排除条目自身、用户无权访问的媒体库以及被内容限制屏蔽的
  条目。条目复用现有 Emby 列表投影，`Fields`、`EnableUserData`、`ImageTypeLimit`、`EnableImageTypes`
  按请求生效。`Limit` 默认 50、上限 1000，空值按未提供，非法值返回 400；条目不存在或不可见返回 404，
  没有相似条目返回 200 空列表。请求成本有上界：最多读取 10 个源 Genre，每个 Genre 最多取 200 个通过
  ACL/可见性/内容限制的候选，之后才聚合排序；`TotalRecordCount` 是这个候选池内的去重数量，不是全库
  相似条目总数。查询只读 `media_item_facets` 与 `media_items` 的现有索引，不解析 NFO、不扫描媒体库，
  也不需要迁移。
- **Emby 实时通道 `GET /embywebsocket`**：Yamby 的"服务器状态/日志"页会连接
  `ws(s)://{host}/embywebsocket?api_key=…&deviceId=…` 并发送 `SessionsStart`、
  `ScheduledTasksInfoStart`；Lux 此前对该路径返回 404，而客户端失败后没有退避地立刻重连，会形成紧凑的
  重连循环。现在根路径与 `/emby/embywebsocket`（大小写不敏感）都完成握手：凭证与其它 Emby 端点相同，
  无效 token 在握手阶段返回 401（不会先升级再关闭），播放票据 token 被拒绝，非管理员可以连接但
  `ScheduledTasksInfoStart` 被静默忽略。服务端按客户端在 `Data` 里给出的间隔（钳制到 1–60 秒）推送
  `Sessions`、`ScheduledTasksInfo` 两类消息，`Data` 与同凭证下 `GET /Sessions`、`GET /ScheduledTasks`
  的响应完全一致（会话 ACL 相同，计划任务仅管理员可见）；`Stop` 停止、`KeepAlive` 应答、未知消息与
  非法 JSON 被忽略且不断开。连接有全局限额与每用户限额（超限在握手前返回 503）、8 KiB 入站帧上限、
  心跳与空闲超时；每一路推送都保证两次推送尝试之间至少间隔 1 秒，连续发 `SessionsStart` 也不能让服务端
  立即重建文档。每次发送都有 10 秒硬超时、写缓冲硬上限 64 KiB（读端停止消费时连接被关闭并释放槽位），
  token 被撤销（401/403）时以 1008 关闭，数据库或访问规则暂时不可用（5xx）时只跳过本次推送、保留连接；
  即使没有活动推送计划也会每 45 秒重新校验 token。关停时会主动发 Close 并退出，不再让长连接拖住优雅
  停机，`serve` 返回错误时同样先排空连接。该端点只轮询既有应用服务，没有引入事件总线，也没有改数据库
  schema。

- **Trakt 评分可以按计划写回旁车 NFO**：`org.lux.trakt-ratings` 插件声明的媒体库级 `RATINGS_SYNC`
  任务现在能真正执行（此前调度器会以“不支持的任务类型”拒绝）。任务默认按 UTC 每周日 04:00 运行；
  每次执行在后台分页遍历该媒体库，只对已有 NFO 旁车的电影、剧集和分集向插件批量查询评分，把可信结果
  按评分写回器已有的格式更新旁车的 `<ratings>` 容器、平铺 `<rating>`/`<votes>`/`<criticrating>`，
  写完主动刷新这些目录的本地元数据，因此详情页和 Emby 客户端马上能看到新分数。没有旁车的条目不查询、
  也不会新建旁车；只在标题上匹配、被插件标记为低置信度、或返回越界数值（分数不在 0-10、票数为负、
  `max` 不是 10、名称非法）的结果一律跳过。同一媒体库同时只允许一个运行，`TRAKT_UNAUTHORIZED` /
  `TRAKT_NOT_CONFIGURED` 会中止整次运行，单条写盘失败只影响该条目。运行没有独立作业记录和界面进度，
  结束时在日志里输出一行 `scanned/queried/written/unchanged/skipped_*/failed` 汇总；每次都是全量重查
  （还没有“条目上次同步时间”标记）。
- **Emby 筛选面板有了官方分级列表**：新增 `GET /OfficialRatings`（根路径与 `/emby` 前缀），返回当前用户
  可见范围内的去重分级值，`Items[]` 用 `Name`/`Id` 表示分级本身，`TotalRecordCount` 是分级个数。数据来自
  内容限制索引里已入库的**归一化分级码**（MPA/TVPG/BBFC 的子集），不在请求里解析 NFO，也没有新增迁移；
  它与条目 `OfficialRating` 字段不是同一份值——后者输出 NFO 原文，所以无法识别的分级不出现，识别出的
  分级也可能与原文写法不同（例如 `Rated R` 在这里是 `R`）。支持 `ParentId`、`IncludeItemTypes`
  （整组都无法识别时返回空列表）、`Recursive`、`StartIndex`/`Limit`（默认 50、上限 1000，`Limit<=0`
  按默认 50，空的 `Limit=` 按未提供处理），媒体库权限和内容限制与普通列表一致。分级目前只能列出，
  `/Items` 还不接受分级筛选（后续任务）。同一批请求的 `GET /Tags` 也从 404 改为返回 200 与
  空列表：Lux 还没有标签数据源（NFO 缓存里没有条目级 tags），筛选面板因此显示空标签而不是请求失败，
  等后续任务补充。

### 修复

- **Emby 查询端点不再因为空的可选数值参数返回 400**：Hills 打开媒体库筛选面板时会对 `/Genres`、
  `/Years`、`/Studios` 发送空的 `Limit=`，服务端此前以 `Limit: cannot parse integer from empty string`
  返回 400，筛选面板因此为空。`Limit`、`StartIndex`、`Sessions` 的 `ActiveWithinSeconds`、`/Search/Hints`
  的分页字段、用户头像的 `Index` 以及 `HideFromResume` 的 `Hide`（含已声明的大小写别名）现在都把空串或
  纯空白按“未提供”处理，与 2026-08-23 对空 `IsFavorite=` 的做法一致，判定逻辑只有一份实现。非空值的校验
  和服务端上限都没变：`Limit=abc`、`StartIndex=-1`、`Index=abc`、`Hide=abc`、超过 1000 的 `Limit` 仍是
  400，`Limit=0` 规则不变，`Hide` 在查询和请求体都没有给出时仍是 400。覆盖 `/Items`、
  `/Users/{userId}/Items` 及其 `Resume`/`Latest`/`NextUp`/`FavoriteItems`、`Shows/*`、`Persons`、
  `Genres`/`Studios`/`Years`、`Library/MediaFolders`、`Users/Query`、`Sessions`、`Search/Hints`、
  `Users/{id}/Images/*` 与 `HideFromResume`，根路径与 `/emby` 前缀行为一致。修复尚未部署，真实客户端的
  筛选面板效果待复测。
- **Emby 列表的 `Filters=IsResumable` / `Filters=IsFavorite` 现在生效**：Emby 列表接口的 `Filters`
  参数此前只识别 `IsPlayed`/`IsUnplayed`，`Filters=IsResumable` 被静默忽略、返回完整列表，
  `Filters` 里的 `IsFavorite` 也不生效（只有单独的 `IsFavorite=true` 参数有效）。现在
  `Filters=IsResumable` 与「继续观看」使用同一套判定（未标记已看、未隐藏续播、达到最小续播进度，且
  低于该用户的已看百分比），只返回当前请求用户有未看完进度的条目；`Filters=IsFavorite` 等价于
  `IsFavorite=true`。过滤器按 AND 组合，因此 `IsResumable` 与 `IsPlayed` 同时出现会返回空列表，而不是
  让其中一个值静默生效。`/Users/{userId}/Items` 与带 `UserId` 的 `/Items`、根路径与 `/emby` 前缀行为
  一致，分页与 `TotalRecordCount` 都基于过滤后的结果。
- **已有光盘图的条目不再被海报覆盖**：刮削器返回的海报图（`Primary`/`Poster`）一直兼作 `DISC` 的
  兜底图，完整刷新时这条兜底会按覆盖策略复用同名文件，把媒体目录里已有的 `disc.jpg` 直接改写成海报的
  字节，结果海报和光盘图变成同一张。现在先写上游明确给出的 `Disc` 候选；只有它全部下载失败、且条目
  完全没有光盘图（媒体目录、已登记的图片记录和 `/config/metadata` 写入目录都没有）时，才用海报兜底
  填充 `DISC`。已经有的光盘图保持原样，符号链接或不可读的 `disc.jpg` 只让这条兜底跳过并记一条脱敏
  警告，不会让整次刷新失败。`POSTER` 本身的行为不变。
- **同一条目的多张同类型图片不再共用一个文件**：一个条目有多张背景图（`FANART/0..n`）时，刷新可能把某个
  索引写到另一索引正在使用的 `-backdrop1.png` 上；被覆盖的那一行仍保留旧的 `contentTag` 和文件大小，图片缓存
  与 ETag 因此失效（真机上表现为背景图不更新或返回错误的 304）。现在写入前会把同一条目里**同类型其它索引**
  占用的路径也算作冲突，只有本行自己的路径可以复用；扫描认可的旁车（`fanart1.jpg` / `fanart2.jpg` 这类）会被
  优先复用，不再另建一份；重扫不会把新文件分配到已被占用的索引，登记层在同一事务里跳过同类型重复路径
  （不同图片类型共用一个文件仍然合法，例如 STRM 缩略图的 `POSTER`/`THUMB`）。已经存在「同类型两行共用一个
  文件」的旧数据不会被自动修复：重扫会跳过这些行，写入会报一次图片尝试失败，需另行清理。
- **保存插件配置后刮削马上按新配置取数**：以前刮削器插件的响应会按「插件 + 方法 + 参数」缓存最长
  24 小时，缓存键里没有插件配置，而保存配置只重启插件进程、不清理这份缓存。改完最小宽度、语言、语言
  回退顺序或 API 地址后，接下来的一次「完整刷新」乃至普通刮削都会继续拿到旧结果，真机上最长要等一天
  才生效。现在保存配置、启用/停用、安装/升级/卸载插件时都会精确清掉该插件的缓存条目（其他插件的缓存
  保留），清理时正在进行的请求也不会把旧配置下取到的响应写回缓存；「完整刷新」现在清理的是真正负责
  刮削的解析器所持有的缓存，不再是空操作。响应缓存的 TTL、命中语义和插件协议均未改变。

## [0.7.14] - 2026-11-05

图片宽度这一套设置删掉了，筛选图交给刮削器插件自己判断；扫描器也学会把 `Season 1 DV`、`Season 1 HDR` 这种同季不同版本的目录合并成一个剧集的多版本。

### 新增

- **同季不同版本的目录会合并成一个剧集的多个版本**：以前 `Season 1 DV`、`Season 1 HDR`、`Season 2 国语` 这类带后缀的季目录会被当成不同的季（或者直接解析失败），同一个季的多个版本散成好几条。现在季目录名在季号后面允许跟一个不带空格的标签（`DV`、`HDR`、`国语`、`DV 1080p` 这种带空格的仍然不认），季号相同就归到同一季，标签只当媒体源的版本名（edition），不进条目身份，所以不同标签的目录会合并成同一个剧集的多个版本源。文件名里自己写了 edition 的，优先用文件名那个。

### 变更

- **主程序不再提供「最小下载宽度」**：图片宽度筛选改由刮削器插件按图片类型自行设置，Lux 不再按上游
  报告的宽度丢弃候选图。管理后台的全局策略、媒体库覆盖和分层图片矩阵里都不再有这一项。已保存设置里
  的 `minDownloadWidth` / `minWidth` 仍能正常加载（不报错、也不丢整份设置），这些键会被忽略并在下次
  保存时自然消失；旧版页面或脚本提交带这些键的请求也不会失败。Emby 的
  `LibraryOptions.ImageOptions[].MinWidth` 为兼容第三方客户端继续输出，值固定为 `0`。

## [0.7.13] - 2026-11-05

纯修 bug 的一版：NFO 里 Emby 写法的评分能读到了，刮削器只给海报地址时封面不再丢，被误判成「没有图」的条目也会继续补图；另外首次启动选了 PostgreSQL 的实例不会卡在空数据库上起不来。

### 修复

- **Emby/Jellyfin 写法的 `<ratings>` 容器现在能读到评分**：旁车 NFO 里的评分此前只认根节点下的平铺
  `<rating>` / `<votes>`，其他工具写成 `<ratings><rating name="tmdb"><value>7.6</value><votes>204</votes>`
  这种容器形式的条目会被静默忽略，详情页、NFO 面板和第三方 Emby 客户端的 `CommunityRating` 都拿不到评分。
  现在容器内按 `default="true"` → TMDb 条目（`tmdb` / `themoviedb`）→ 第一个可读条目的顺序取值，`max`
  不是 10 时归一到 0-10，票数取同一条目；平铺字段仍然优先，两种写法不会把一家的分值和另一家的票数凑在一起。
  `<userrating>` 继续不读取（Lux 没有个人评分字段），评分来源仍记为 NFO。
- **刮削器只给了海报字段时不再丢封面**：此前只要候选 JSON 里带 `images` 对象（哪怕没有
  `POSTER` / `FANART` 条目），选片写图就完全按类型图走，插件 `get` 返回的 `PosterUrl` /
  `BackdropUrl` 被直接忽略。TMDb 插件在首选语言下拿不到图（例如请求语言用了 `zh-CN` 而
  TMDb 图片按 `zh` 标记）、图片接口报错或根本没有类型图时，就会出现「元数据刮到了、封面是空的」。
  现在按图片类型逐个判断：类型图里没有 `POSTER` / `FANART` 时，回退到候选的
  `PosterUrl` / `BackdropUrl`，媒体库图片策略（开关、来源、覆盖、张数上限）照旧生效。
- **上游给了海报字段的条目不再被永久判成「没有图」**：类型图接口返回空列表时，Lux 会把该条目参与的
  图片类型整批记成 `UNAVAILABLE / NO_IMAGE`，之后的「补全」认为这块已经查过，连图片接口都不再请求，
  于是永远停在「有 NFO、没封面」的状态（只有手动重新识别/完整刷新才会重来一次）。现在只有在上游连
  `PosterUrl` / `BackdropUrl` 都没给时才记录这种「确实没有图」；只要元数据里还有海报或背景图地址，
  `POSTER` / `DISC` 或 `FANART` / `THUMB` / `BANNER` / `ART` / `WALLPAPER` 就继续算缺图，交给回退逻辑落盘。
- **首次启动时选了 PostgreSQL 会卡在空数据库上起不来**：第一次启动还没选数据库时，向导会先开一个占位的 SQLite 库，开它的时候就顺手写了 `server-state.json`。等你在向导里改成 PostgreSQL、进程重启，启动检查读到这个标记，再看新库空着、没有 `server_id`，直接以 `EmptyDatabase` 拒绝启动。现在两头都堵住了：数据库还没选定的时候根本不写这个标记，占位库不会留下「这台服务器已经初始化过」的痕迹；已经被旧版本弄坏的目录也能自愈——PostgreSQL 空库启动时，如果标记里的 `serverId` 正好等于配置目录里 `lux.db` 的身份、而那个库从来没有过用户，就认定这标记来自没被用过的占位库，清掉它让选好的数据库正常启动。有任何疑问（标记或库读不到、身份对不上、库里有用户）都保留原来的保护，已经初始化过的实例不受影响。

## [0.7.12] - 2026-11-05

这一版主要动日志和管理后台：Emby 图片改成按客户端要的尺寸走缓存，每张图片留一行脱敏诊断，运行日志也全部过一遍脱敏；仪表盘的活动记录改读索引、默认只留 7 天；登录失败有了固定的日志事件。顺手把详情页一堆分隔线去掉了，后台也打开得快一点。

### 新增

- **Emby 图片请求有了脱敏诊断日志**：每成功返回一张 Emby 图片，都会在 `luxd::emby_image_diag` 这个
  日志 target 下留一行（鉴权失败、404/5xx 等没有返回图片的请求不产生这一行）：客户端/设备名（`X-Emby-Client`、`Authorization` 头或 User-Agent 产品名，
  截断到 32 字符并过滤字符）、图片类型、鉴权方式（登录 / 图片 tag / Filmly 兼容）、客户端传的
  `maxWidth`/`maxHeight`/`width`/`height`/`quality`/`format` 和叠加参数，以及最终去向：命中哪一档
  变体（`variant_width`），还是回退原图及原因（`no_size_hint`、`non_jpeg_format`、`overlay`、
  `source_size_unknown`、`needs_original`、`variant_unavailable`）。日志里没有 token、API key、
  完整 URL/查询串、Cookie、IP 和条目 ID；响应字节、状态码与头完全不变。

### 变更

- **管理仪表盘的「近期活动」不再加载封面与章节数据**：活动流只显示剧集标题、季号和季数，取数时跳过图片标签和章节查询，打开控制台时少两组逐条目的查询；响应字段、条目排序、24 条上限与登录/播放各 12 条的配额都不变。「正在播放」区域仍要显示封面，继续走原来的完整取数路径。

### 修复

- **回退到服务端计划后还被当成已停止**：播放器看门狗把播放切到服务端计划后，起播状态不再丢，播放中的会话不会莫名其妙被标成已停止。
- **回退后没重载播放引擎**：切到服务端计划时会重新加载引擎，不再沿用已经失败的原生解码状态。
- **弹幕接口 404 被当成报错**：现在视为「这条没有弹幕」，返回空结果，而且只请求一次。
- **非内置 webhook 不显示接收地址**：这个输入框只在内置 webhook 下出现。

## [0.7.6] - 2026-11-02

Web 播放这版补齐了播放页内的音轨切换、按分辨率选画质，以及客户端解码失败自动回退服务端转码；管理端转码页重做。

### 新增

- **自动连播下一集**：一集播完先弹一张 10 秒倒计时卡，可以「立即播放」也可以取消，结束后跳下一集并自动起播。设置面板加了「自动连播下一集」开关，复用账户偏好 `autoPlayNextEpisode`；进到 `CREDITS_START` 章节后出现「跳过片尾」按钮。

- **手动画质上限（码率）**：`POST /api/v1/playback/sessions` 和 `/playback/bootstrap` 新增可选 `maxBitrate`（100 kbps–200 Mbps），源码率超过上限就按 0–4 档位升级到能重编码的档位。响应新增 `bitrate`（`sourceBitrate`/`maxBitrate`/`targetBitrate`/`limited`），其中 `targetBitrate` 和 FFmpeg 实际的 `-b:v` 一致，管理员设的码率上限也算在里面。

### 变更

- **浏览器端软解 HEVC 限制到 ≤1080p**：更高分辨率走服务端转码，原生 HEVC remux 路径不受影响。取舍和实测记录在 `docs/COMPATIBILITY.md` 的「Web 播放：客户端解码回退与原生直放门控」。
- **奇数分辨率上限向下取偶**：`maxHeight` 和管理员的 `max_output_height` 在缩放滤镜、`targetHeight`、码率查表处统一向下取偶（1081 → 1080），避免编码器报 `height not divisible by 2`；`resolution.maxHeight` 仍然回显请求值。`targetHeight` 只在真正重编码时给确定值，Direct 和拷贝档位报源高度，UNSUPPORTED 为空。
- **规则文档对齐**：README 和 agent 规则都改成「分层 Web 播放 + 受限转码在范围内」（ADR-004 / ADR-026）。
- **路线图盘点**：新增 `docs/TODO-ROADMAP.md`，按规格、代码、测试和兼容性记录盘出产品完整度候选清单。只盘点，开工前每项还是要立单独的 `LUX-*` 任务。

### 修复

- **4K HEVC 等 MKV 在浏览器里重新封装失败**（`MKV MSE SourceBuffer append failed`）：解封装库返回的是 Buffer 视图，MP4Box 写入时忽略 `byteOffset`，导致 `hvcC`/`avcC`/`vpcC`/`av1C` 和样本数据错位。现在统一拷贝成独立数组，并加了回归测试。
- **客户端解码卡死不回退**：DIRECT 计划下任何客户端引擎失败（MSE append 失败、编码串不被支持、worker 报错、12 秒没首段、持续低于 0.5× 实时）都先回退一次服务端转码；原生直放 20 秒没有 `readyState≥2` 同样回退。
- **原生 MKV 直放的静默失败**：只有 h264/hevc/vp9/av1 才允许原生 MKV 直放（此前未知编码默认当 `avc1`，MPEG-4 视频会出现“有声音没画面”）；有视频流但 `videoWidth === 0`、有音频流但浏览器报告音频解码字节为 0 时自动回退，回退请求也不再信任浏览器对 ac-3/ec-3/mpeg4 的“可播放”回答。
- **10-bit 探测更准**：10-bit H.264/VP9/AV1 改用真实位深编码串探测。
- **自动连播的边角**：自动起播标记只在同集重载时保留一次，终态失败就清掉；倒计时卡片不再逐秒播报；自动连播偏好首次读取不再覆盖用户的手动切换。
- **播放页交互**：音轨选择用 URL 结果判空；服务端会话重复点击不再重建；播放提示不再使用已经被覆盖的会话错误；未知 403 错误码不再套用转码策略的文案。

## [0.7.5] - 2026-11-01

第三轮性能版本，这版主要在省后台空转：空闲唤醒从定时轮询改成写事件驱动，HLS 和元数据路径上的重复读写收紧了，手机端后台换成底部标签栏。

### 新增

- **手机端底部标签栏**：宽度 <900px 时侧栏换成悬浮的底部标签栏（看板、媒体库、插件、通知、更多），其余入口收进「更多」抽屉。看板在手机上把媒体数、用户数排成一行，资源卡也更紧凑；桌面布局不变。
- **看板合并成一张资源卡**：桌面端首屏把主卡和三个计数排在同一行，CPU、内存与存储从三块卡片合成一张资源卡（桌面三列、手机各占一行），层次清楚多了。
- **内存也显示百分比了**：容器有 cgroup 限制时按限制值算，没有限制就回退到宿主机物理内存（`/proc/meminfo`，新增 `hostTotalBytes`），所以内存也有百分比和进度条。并发节流仍然用原来的 `usagePercent`，口径没变。
- **播放活动日志能直接读**：系统日志里的播放活动改成可读文案，剧集按「剧集 · 季 · 集 · 标题」命名。播放活动审计记录会保存媒体条目标题，系统日志行也能直接显示条目名称。

### 变更

- **空闲唤醒改成写事件驱动**：本地元数据 outbox 不再每 250 ms 轮询（它以前占空闲唤醒的一半），邮件投递、Webhook、全局合集、派生数据 outbox 和读模型消费者都在写入提交后被立刻唤醒。只保留一个兜底间隔：邮件/合集/读模型到 5–10 秒级，Webhook 30 秒，库根回退 5 分钟。
- **播放会话回收按到期时间休眠**：Web 播放会话回收不再每 5 秒查两次，改成按最近到期时间睡下去、会话创建时唤醒。
- **播放准入 30 秒一次**：分片和清单请求不再各跑一次完整的准入（`BEGIN IMMEDIATE` + 计数 + upsert），先做只读检查，超过 30 秒窗口才重做一次完整准入，并重估并发上限与 `can_play`。代价是权限撤销最迟在 30 秒加一个分片周期后才生效。
- **元数据任务批量预取**：领取一批任务后一次读出刮削器配置和尝试历史，备份快照在真正能写入前复用，候选搜索的能力行改成一次事务写入。管理页的待处理计数改为按需计算，前端只刷新正在订阅的查询。
- **人物页整页一个事务**：演员页的解析不再每页开一堆事务。
- **图片写入合并成一次提交**：图片行和尝试完成记录一起提交。
- **重复写入与查询减负**：重扫、合集重同步、元数据回写里值没变的写入直接跳过；搜索分页直接用匹配查询已经读到的排序标题排序，不再二次 JOIN `media_items`；过期 PENDING 候选的清理有了专用索引（迁移 `0244` / `0246`）。
- **缓存与轮询收紧**：可信代理 CIDR 的解析结果按 epoch 缓存在 state 上，设置一写入就失效；转码管理页的轮询压到一条语句，历史写入一次提交。
- **升级前请先备份**：从 0.7.4 升到 0.7.5 时，启动会自动执行 1 对迁移（`0244` / `0246`，过期候选清理索引）。migration 只向前、**不支持回滚**，升级前请备份 `/config`、`/media`（用 PostgreSQL 的话连数据库一起）。

### 修复

- **播放中撤权不生效**：上一版每个分片都会续期准入，`last_seen_at` 一直被刷新，30 秒窗口永远不到期，整场播放只做过一次完整准入——并发上限和 `can_play` 就此冻结，播放中撤销权限也不会拒绝下一个分片。现在资产请求只做只读检查，超过窗口才重做准入。
- **库页缓存来回翻转**：库页预热把 `read_model_mode: off` 写死了，请求走派生页、下一次预热又写回权威页，同一页在两种来源之间来回。现在预热跟随配置，`shadow` 明确降级成 `off`，免得为没人比较的页面付比对查询。
- **探测失败会跳过 drain**：关停时探测失败不再连累用户清理、Web 播放、插件和库监听的 drain；用户保留清理每轮跑完整批，不再每分钟欠下 60 倍的账，首次清理提前到启动 60 秒后。邮件唤醒绑定到所属数据库实例，两个 worker 不再互相抢唤醒。
- **扫描重建后消费者会被叫醒**：扫描重建条目时显式唤醒消费者；读模型消费者的失败步骤 1 秒后重试，合集的重试延迟不再被写入信号打断。NFO 批处理在关停时会被 drain，outbox 的关停信号改为永久生效。
- **手动跑完元数据任务不刷新**：现在所有任务变体都会刷新；演员页事务在分页读取失败后仍可继续使用。

## [0.7.4] - 2026-10-31

第二轮性能版本：去掉播放进度、鉴权、访问检查、读路径和 outbox 上的重复工作，顺手修掉了 outbox 无限重排把磁盘撑满的事故。

### 新增

- **SQLite 同步级别可配**：`LUX_SQLITE_SYNCHRONOUS` 让 SQLite 连接可以配 `full`（默认）或 `normal`，每条新建连接执行一次 `PRAGMA synchronous`。WAL 下 NORMAL 仍然崩溃安全，断电最多丢最后几次提交，所以做成部署选择而不是默认值。非法值回退 `FULL` 并留一条告警，启动日志会写实际生效的级别，方便在 NAS 上做 A/B（过程见 `docs/DEPLOYMENT.md`）。
- **详情页顶部横版背景**：详情页顶部按横版图的原始高度展示，并渐隐到页面底色，不再拉伸铺满整屏。剧集、季、集共用剧集图，横版图（fanart → thumb）优先于海报，左侧加重遮罩保证标题和简介读得清。
- **删除进度挪到媒体库页**：删除任务从「运营 → 运行记录」移到媒体库页，用新的 OPEN（非 COMPLETED）筛选只列没跑完的删除，展示阶段、已处理记录数、稳定错误码和重试，并沿用 202 响应的初值轮询。运行记录页不再长期挂着已经完成的一次性删除。
- **STRM 探测失败写清原因**：失败结果带上库内相对路径、目标类型和耗时；附带文件、缩略图写入和注册失败也报告底层错误，不再是一句笼统的失败。
- **膨胀后的回收手册**：新增 `docs/RUNBOOK-OUTBOX-BLOAT.md`，讲已经膨胀的部署怎么安全把空间收回来。

### 变更

- **播放进度写入合流**：客户端和 Web 播放器每 10 秒上报一次进度，普通 tick 在内存里合流，最多 30 秒落盘一次（合并取最大值）；开始、暂停、恢复、停止、可能翻转「已看」或跨过续播阈值的 tick 仍然立即写。代价是崩溃最多丢一个窗口的进度，其他设备的续播位置最多晚一个窗口。
- **派生状态按需刷新**：续播指针、整季/系列的已看聚合和播放准入刷新只在播放状态变化或「已看」翻转时执行。`user_series_next` 从「先删后插」改成单事务 UPSERT，读者不会在中间看到空指针。
- **鉴权结果缓存 5 秒**：Web 与 Emby 的主体解析结果缓存 5 秒，但只缓存凭据本身——IP/设备/客户端规则每次请求都用访问 IP 解析器的结果重新判定，撤销、禁用、删除、改密、改规则在下一个请求就可见（缓存项带 epoch，写操作立即失效）。Emby 侧合并成一次 JOIN。
- **访问限制策略缓存 5 秒**：每用户的内容限制策略缓存 5 秒并按用户版本失效，媒体库授权、条目分级和标签仍按请求/条目读取。播放访问的「允许」结果按 `(用户, 条目, 媒体库)` 缓存 60 秒，「拒绝」不缓存。
- **用户级事件只推给本人**：进度、收藏、已看、账户偏好、续播可见性这些用户级事件带上用户和条目，只推给该用户的 SSE 连接，播放进度走独立的 `progress` 作用域；扫描、元数据、管理员编辑等目录级事件仍然广播。前端对进度事件只失效续播和对应条目的播放键。
- **首页按用户缓存**：继续观看、最近添加、各库最新、库列表和推荐一起按用户缓存（五条 rail 一个快照）。失效拆成「目录级」（扫描、元数据、合并、删除、库生命周期、服务器设置）和「用户级」（只影响本人的偏好、已看阈值等）。
- **列表页改用摘要投影**：网格页和读模型页用摘要投影读取，不再 join 媒体源与流，也不带每行 4 个图片子查询。详情页和 Emby `Fields=MediaSources` 仍走完整投影。
- **图片路径解析结果缓存**：通过包含性校验的解析结果按 `(image_id, content_tag)` 缓存；命中时会重新校验数据库路径、库根和父目录，父目录被换成指向库外的链接就回到完整 canonicalize 流程。删除、替换、移动和越界都会让条目失效。
- **写入少一次索引维护**：重扫、元数据重查、合集重同步里值没变的 UPDATE 直接跳过（NULL 安全的 `IS DISTINCT FROM`，两个后端同一条语句）。去掉两个被更宽索引完全覆盖的 `media_items` 部分索引（迁移 `0242` / `0244`），涉及 `parent_id`/`series_id`/`removed_at` 的写入少一次索引维护。
- **升级前请先备份**：从 0.7.3 升到 0.7.4 时，启动会自动执行 2 对迁移（`0242`/`0244` 删冗余索引、`0243`/`0245` 拆 `search_outbox`），首次升级会把全部条目重新入队一次来重建搜索索引。migration 只向前、**不支持回滚**；PostgreSQL 部署不要回退到拆表之前的旧二进制，见 `docs/COMPATIBILITY.md` 的「search_outbox 拆表」。

### 修复

- **队列无限重排撑满磁盘**：搜索事件和读模型事件共用一个 outbox 表和一个 id 序列，缺口判定拿单一 kind 的 `MIN(id)` 去比混合序列的水位，每一拍都误报缺口并把全部条目重新入队——一晚上 6.97 亿行、89 GB，把 `/vol1` 撑满，PostgreSQL 写失败、全站 503。现在搜索事件拆到独立的 `search_outbox`（迁移 `0243` / `0245`），消费者改名 `search_reindex@2`，升级时自动把全部条目入队一次；批量读取按 kind 过滤、走 `(kind, id)` 索引；缺口修复只做一次全量重排，每个消费者 5 分钟冷却，队列超过 200 万待处理行就拒绝并记 ERROR；回收（trim）改成每处理一批就执行，旧版本留在 `catalog_outbox` 里的 `search` 行由后台分批清理。已经膨胀的部署按 `docs/RUNBOOK-OUTBOX-BLOAT.md` 回收空间（`TRUNCATE` 后读模型由一次全量重排重新收敛），PostgreSQL 部署不要回退到旧二进制，见 `docs/COMPATIBILITY.md` 的「search_outbox 拆表」。
- **续播位置在阈值处不更新**：跨过续播阈值的 tick 现在会立即刷新续播指针，不再等下一个状态变化。
- **进度回调不再加载整条详情**：普通进度 tick 复用已存的时长，不再为了取 duration 拉一遍详情；播放入口重复的媒体库查询合并成一次。
- **PostgreSQL 起不来**：这个问题是 0.7.4 里引入、本版修掉的。连接池的 `after_connect` 把多语句的会话设置（`SET TIME ZONE`、`statement_timeout`、`idle_in_transaction_session_timeout`、`work_mem`、`jit` 等）改成走预处理语句，PostgreSQL 以 `cannot insert multiple commands into a prepared statement` 拒绝，于是每个新连接都失败、连接池超时、进程起不来。现在这条路固定走简单查询协议，SQLite 侧的多条 `PRAGMA` 也恢复成一次执行。会话设置最终都落在连接上：时区 UTC、`application_name=lux`、`work_mem=16MB`、`jit=off`，两个超时也照旧。

## [0.7.3] - 2026-10-31

这版围着安装流程转：只有向导在跑、装完自动重启、被打断的首扫自己续跑；后台审计和运营界面也一起补了可读性。

### 新增

- **未初始化时只挂安装向导**：第一个管理员存在之前，只挂载安装向导、健康检查和 Emby 的三个公开发现路由（`System/Ping` 返回 200、`System/Info/Public` 报 `StartupWizardCompleted: false`、`Users/Public` 返回空列表），业务路由不注册，访问未知路径拿到的是 Lux JSON 404 或 Emby 裸 404，而不是进了业务处理器再报内部错误。初始化判断读的是和 setup 接口同一个事实（有没有用户），判断不了时按就绪处理。
- **装完自动重启**：`POST /setup/complete` 在 201 写完之后自己请求重启（默认延迟 250 ms，靠 `axum::serve` 排空在途请求保证送达），响应体新增 `restarting`。
- **前端会等它回来**：Web 端在 `restarting: true` 时显示全屏「正在重启 Lux」，每秒探测一次 `setup/status`、每次 3 秒超时，连接断开 60 秒还没恢复就提示查日志并提供刷新；端口一直没关闭时按 10 秒兜底离开等待页。只有真正的 Lux 状态响应（`initialized === true`）才算恢复，反代返回的维护页不会被误认。
- **被打断的首扫会自己续跑**：安装完成后的重启会以 `SERVER_SHUTDOWN` 取消首扫，媒体库因此一直是空的。新进程启动时会挑出「最近一次 `RECONCILE_LIBRARY` 被 `SERVER_SHUTDOWN` 取消、库仍启用、`last_scan_at` 为空、有媒体根、没有活动扫描」的库自动排队。
- **续扫的限额**：排队前会实测根路径（单根 5 秒上限、同一挂载只探测一次、并发上限 4，丢了挂载也不会拖住启动），至少一个根可用才真正排队，顺带修正过期的 `is_available` 标志。单次启动最多处理 512 个候选库，日志会写明本轮排队数和仍符合条件的剩余库数（截断时写「至少」）；同一个库被关停打断 3 次还没成功扫过，就停止自动补扫，改由管理员手动触发。
- **审计记录带上更多上下文**：媒体库创建/更新记录名称、根路径与封面；扫描开始记录媒体库和任务类型；取消扫描、STRM 探测、章节、元数据匹配、人物索引重建都记录所属媒体库，以及取消前后的状态。
- **系统日志能读了**：审计事件类型和目标类型映射成中文名，未知类型显示原始代码；媒体库目标和 `libraryId` 元数据解析成库名。元数据按「标签 / 值」成行展示，不再是一段 JSON。
- **运营与通知页重新排版**：运营页改成统计卡、分段标签、带状态栏的运行卡片和控制台式日志；通知页改成双栏工作区，含目标卡片和投递时间线。类名和 ARIA 没变。
- **播放计划给出直放候选顺序**：响应新增 `candidates: [{ kind: "proxy" | "lux" | "origin", url }]`：`proxy` 是带 `PlaySessionId`、`DeviceId`、`UserId`、`static=true` 和播放专用短期 `api_key` 的标准 Emby 流入口，`lux` 是签名入口，`origin` 是 HTTP(S) `.strm` 目标。旧的 `url`/`proxyUrl`/`rangeUrl` 再保留一个版本，Web 直接按服务端给的顺序试。
- **播放令牌只认一个条目**：令牌形如 `luxpb_{条目}_{随机串}`，路由层不用查库就能把 `Items`、`Users/Items`、`Videos` 限制在该条目上。令牌签发不了（比如黑名单命中）时省略 `proxy` 候选。
- **API 类型自动生成**：`scripts/generate-api-types.sh` 把 Web DTO 生成到 `web/src/lib/api/generated/`，条目图片、元数据、弹幕信息等试点类型改由生成文件再导出（原有导出名和其余代码不变）。类型漂移检查会在 CI 失败时指出新增或改名的文件。

### 变更

- **启动修复按版本只跑一次**：新增 `startup_repair:<name>` 版本标记，成功后记下版本，失败或无事可做时释放标记留给下次。并发启动不会双跑，崩溃遗留的标记一小时后过期。
- **占位符改写按语句缓存**：PostgreSQL 的静态 SQL 把 `?` 改写成 `$n` 时做了记忆化，真实形态（约 1100 条静态语句 × 8 线程）大约快 4.7 倍；分片改用乘法散列避免热点。
- **库根只查一次**：`MediaFolders` 的库根查询合并成一次批量，不再每个库查一遍。
- **清理任务不再反复抢锁**：已经完成的清理声明会被跳过，不再反复抢同一把锁。
- **页面隐藏时停止采样**：播放信息面板的客户端统计采样在页面隐藏时暂停，不再空转。

### 修复

- **硬件编码器自检更准**：QSV 像 VAAPI 一样上传 NV12 帧，自检改用 yuv420p 帧探测。自检失败时会给出真实原因，不再是笼统的错误。
- **阻塞调用不再占核心线程**：设备与符号链接探测改到阻塞线程执行，并在开始服务请求前解析完成；插件归档的 `stat` 和批处理 walker 的根 canonicalize 也不占核心线程了。
- **键位监听只绑一次**：播放器的 keydown 监听每次挂载只绑定一次。
- **冒烟脚本会等重启恢复**：所有脚本都会等安装重启后的恢复，代理演练同样等首扫完成，不再把重启前的旧任务当成恢复结果。
- **类型生成前清空环境变量**：生成前会清掉所有 `TS_RS_*` 环境变量，避免外部变量改变输出。

## [0.7.2] - 2026-10-30

插件商店能同时配多个目录并在本地合并，Emby 令牌收成播放专用，Web 直放补了候选链，浅色主题改用语义状态色。

### 新增

- **插件商店支持多个目录**：管理员可以同时保存最多 10 个 HTTPS 目录地址，已填的以可移除标签显示，重复地址自动去重。多个目录并发拉取，单个目录失败只记告警、不影响其它目录，合并后按插件 ID 去重并取最高 SemVer 版本。旧版单地址配置（`plugin_store_url`）和 `{ "url": ... }` 请求字段继续兼容，空列表回退默认仓库。
- **Emby 令牌收成播放专用**：新建的 Emby 访问令牌带 `scope=PLAYBACK` 并绑定播放会话，随会话结束过期（最长 12 小时），使用时不刷新。除 `Items/{id}`、`Users/{id}/Items/{id}`、`Videos/{id}/stream|original`、`Auth/Keys` 外，其余 Emby 路径一律 401，默认令牌解析、登录会话列表和设备校验都不接受它。停止或回收会话即吊销，浏览器历史里留下的媒体 URL 随之失效。
- **Web 直放会挨个试候选**：远程 HTTP(S) `.strm` 依次尝试同源 Emby 流入口（302 代理可接管）、签名 Lux 入口、origin；某个候选 8 秒内报错或拿不到元数据就换下一个。可用类型会被记住（只记类型），下次失败就忘掉。
- **查询统计自动就绪**：服务器已经预加载 `pg_stat_statements` 时，Lux 启动后会在业务库自动创建该扩展，管理员数据库诊断随即能返回 `queryStatistics`。这需要超级用户权限，失败只记警告；`LUX_POSTGRES_QUERY_STATISTICS_EXTENSION=0` 可以关掉。
- **继续观看的文案分场景**：先按进度状态（即将看完、刚开始、下一集），再按时间段和电影/剧集措辞，不再统一是「看到这里」。
- **只列出本机可用的硬件编码器**：启动时探测设备节点（macOS 的 VideoToolbox、NVENC 的 `/dev/nvidiactl`、VAAPI 的 DRM render node、QSV 的 Intel vendor ID），设置页只展示检测到的编码器。已保存的选择仍然可见，免得在没有对应硬件的机器上选错档。

### 变更

- **容器里的访问 IP 认对了**：Docker 发布端口会把源地址改写成网桥网关，严格的可信代理列表匹配不到连接对端，会话就一律记成 `172.31.0.1` 这类地址。现在启动时从 `/proc/net/route`（回退 `/proc/net/ipv6_route`）读默认网关，把这一个主机地址并入可信列表；显式 `trustedProxyCidrs` 仍然累加，非容器部署行为不变。
- **用户列表工具栏更扁**：去掉工具栏外层卡片和重复的人数显示，人数回到分页行（`显示 X–Y 条，共 N 条`），排序下拉使用统一样式。
- **浅色主题改用语义状态色**：后台状态、插件控件和媒体弹窗里写死的深色十六进制值换成 `--lux-status-*` 令牌，浅色下每个令牌都满足 4.5:1 对比度。删除按钮有了独立的浅色配色，批量操作结果改用 `is-success`/`is-failure` 样式而不是内联颜色。

### 修复

- **空闲时一直占 CPU**：电影 NFO 合集身份对账 worker 每秒轮询一次，在 PostgreSQL 上同时踩了三个坑——重读语句对 `LEFT JOIN` 用裸 `FOR UPDATE` 被拒绝，待处理项永远留在队首；部分索引仍要求已经不再读取的 `nfo_metadata_json`，每次轮询都顺主键扫完 `media_items`；SQLite 的目录约束重建清单里缺这个索引，全新库里根本没有。
- **对账轮询不再扫全表**：改成按 `FOR UPDATE OF item` 加锁，两个后端都重建索引（SQLite `0240`、PostgreSQL `0242`），并把 `LIMIT` 隔离在连接之外让该索引成为驱动，生产规模数据上单次从约 177 ms 降到约 6 ms。
- **推荐统计能刷新了**：指纹查询里的 `SUM(...)` 在 PostgreSQL 返回 `NUMERIC`，`Any` 驱动解不出来；现在显式转成 `BIGINT`。
- **读模型终于真的就绪**：重建完成时写入的水位名 `catalog_items_rebuild` 和读取方、增量消费者检查的 `catalog_items_rebuild@N` 对不上，结果所有读取退回权威查询、每次启动整体重建、增量消费者不运行、`catalog_outbox` 一直堆。现在统一写带版本号的名字，统计重算改成单事务，读者不会看到被清空的计数表。升级后的首次启动会触发一次队列缺口恢复，把全部条目重新入队并增量处理。
- **搜索表没变化就不重写**：`media_search` 的重建 upsert 只在标题、排序标题、原始标题或别名真的变了才更新。
- **探测超时放宽到 130 秒**：探测原来沿用插件默认的 30 秒调用预算，既等于插件自己的 ffprobe 上限，又短于缩略图路径，慢速远程源会被宿主杀掉。相对本地目标按 `.strm` 文件所在目录解析，SMB 和其他不支持的协议直接给出原因，不再交给 ffprobe。
- **「正在播放」卡片排版修正**：卡片左对齐，剧集显示所属剧集海报，不再沿用单集的残留图。

## [0.7.0] - 2026-10-29

这版把读模型和搜索索引改成「派生表 + 队列消费者」，协议层加了 gzip/ETag，也交代了升级的一次性成本。

### 新增

- **读模型换成派生表**：新增 `catalog_items`/`catalog_item_stats`/`user_series_next` 三个派生读模型，带后台重建、中断续建和行数/校验和校验。`LUX_READ_MODEL_MODE=off|shadow|on` 三档开关默认 `off`，打开后首页、继续观看、库列表与详情改走派生表，关掉时响应保持逐字节一致。
- **搜索索引改成入队重建**：写事务只往 `catalog_outbox` 追加事件，消费者批量重建索引；搜索请求前有界排空 200 条、后台每拍 500 条，扫描积压不再让单个请求买单。SQLite 和 PostgreSQL 语义一致，PostgreSQL 侧第一次有了等价实现。
- **搜索可以不算总数**：支持 `count=false`（Lux）和 `EnableTotalRecordCount=false`（Emby），返回页面和排序不变、跳过总数计算，总数报 0；默认仍返回精确总数。
- **响应压缩与 ETag**：成功的 JSON 响应按需 gzip，并下发基于**未压缩** body 的强 ETag，`If-None-Match` 命中返回 304。媒体流、图片、SPA 回退、SSE 和 Range 请求不受影响。
- **详情 NFO 解码结果缓存**：重复打开同一详情时跳过 130 KB 级 JSON 的读取和解析；缓存按条目指纹 + 字节数 + 更新时间校验，写入或修复会自动失效。
- **列表补齐媒体流字段**：显式请求 `Fields=MediaStreams` 时补齐顶层 `MediaStreams`，此前会被静默丢掉。
- **前台变慢时后台自动让路**：`LUX_BACKGROUND_FOREGROUND_THROTTLE=on` 打开（默认关闭），阈值用 `LUX_BACKGROUND_FOREGROUND_P95_MS` 调；前台变慢时 probe/NFO/图片并发按比例回落，冷却后自动恢复。
- **删掉条目，播放历史还在**：条目被删除后导入的播放历史事件仍然保留，并按同一 provider 身份恢复到重新识别出的条目上；`source` 和 `source_event_key` 仍是导入幂等键，恢复时遇到已存在的同一事件只留一条，不会重复计数。和观看状态一样，没识别出身份的条目继续保留原行，不做猜测性匹配。归档只在该条目真正被硬删除时发生（媒体库删除、保留期清理），所以「文件挪位置、扫描生成新条目」要等旧条目清理完历史才回到新条目。
- **观看状态跟着作品走**：已看、收藏、播放次数、续播位置在条目被删除后保留，并按 provider 身份（TMDb、IMDb 等）重新挂到同一部作品上。删除媒体库、把资源换到另一个媒体库，或者文件挪位置后扫描生成了新条目，只要重新识别到同一身份，历史就会自动回到该条目；没识别出身份的继续保留原行，不会被误配到同名的其他作品。同一编号的电影与剧集按条目类型区分。

### 变更

- **扫描空闲退避**：批量排空循环从固定 50 ms 改成自适应 250 ms–1 s，任一轮有进展就重置。
- **存储层按触达域拆分**：邮件 outbox、邀请/注册邮件流程拆开，对外行为没变。
- **升级前请先备份**：从 0.6.20 升到 0.7.0 时首次启动会自动执行 14 对迁移并在后台重建读模型。66k 夹具上重建约 3 秒、数据库体积 +16%（322.0 → 374.7 MB），条目越多越久；migration 只向前、**不支持回滚**，升级前请备份 `/config`、`/media`（用 PostgreSQL 的话连数据库一起）。
- **统计信息定期维护**：有媒体条目后执行一次全量 `ANALYZE`，之后每 15 分钟跑 `PRAGMA optimize`，扫描或元数据任务运行时让路。空库不采集统计，免得把「每张表一行」的估算写进 `sqlite_stat1` 后长期影响执行计划。
- **空间回收给播放让路**：有人在播放时暂停回收，不再跟播放进度写入抢 SQLite 写锁。
- **单文件即可完整备份**：每个数据库连接设置 `journal_size_limit`，正常关闭时截断 WAL，使 `lux.db` 单文件就是完整数据库，按文件备份即可。
- **慢写入会被记下来**：SQLite 写锁等待超过 1 秒时记录操作名和实际等待时长，方便定位「某个写入为什么慢」。

### 修复

- **坏掉的 NFO 缓存会被重建**：损坏或超限的缓存行仍会被识别、清除并等后台重建；缓存命中条件包含字节数和更新时间，不只看指纹。
- **库文件不见了就不启动**：已初始化过的配置目录在数据库文件缺失或为空时拒绝启动并打印恢复指引，不再静默创建空库、重跑 migration 并展示安装向导。确需从空库重来时，删掉 `/config/server-state.json` 再启动。

## [0.6.9] - 2026-10-17

### 新增

- **后台共用一个 CPU 预算**：扫描准备、指纹、后台 NFO/图片计算、本地媒体探测和缩略图共享进程级 CPU 预算，按 CPU/cgroup 容量自动设置，也能用环境变量调整。
- **ffprobe 并发会自动调**：本地 ffprobe 按有效 CPU 容量定自动进程预算，再按近期探测完成速率自适应调整；首页延迟变高或容器内存吃紧时会保护性降档。
- **扫描指纹换新格式**：指纹格式开始带版本，可靠的文件状态快照可以复用；旧指纹在低速后台任务里慢慢迁移。
- **STRM 探测队列门槛**：没配媒体信息插件的 `.strm` 来源标记为 `NOT_CONFIGURED`，不进普通本地探测队列；插件配置变化或重新启用后，会自动给选中的媒体库创建持久化探测任务。
- **自动补信息任务退避重试**：自动 `FILL_MISSING` 任务在刮削器暂时不可用时按条目退避重试；服务重启后恢复未完成的任务，任务 ID 保持不变。

### 变更

- **扫描查询少拼 SQL 字符串**：filesystem 和 Manifest 的扫描查询复用有界 SQL 模板缓存，重复构造 SQL 文本和参数占位的开销减少。
- **删除差异改为分页**：Manifest 删除差异按 root/path keyset 分页，用 `EXISTS` 判断还有没有差异；各版本工作流的删除范围含义没变。
- **扫描发现分片提交**：SQLite 下的 Manifest discovery 按 4,000 文件默认预算分片，后续分片失败时保留已提交进度以便恢复；PostgreSQL 仍然走原来的批次路径。
- **自动并发默认开启**：Docker Compose 默认启用 ffprobe 自动并发预算，后台 CPU 名额在扫描、元数据、图片、ffprobe 和缩略图之间共享。
- **活动弹窗只盯在跑的任务**：管理员的活动弹窗聚焦正在运行的任务，已完成的扫描阶段不再占着活动列表。
- **自动识别失败原因分得清**：没有候选是 `NO_CANDIDATE`，候选分数不足是 `LOW_CONFIDENCE`；低分候选留着给管理员复核，管理页会显示具体原因。

### 修复

- **ffprobe 预算回收**：取消或超时的 ffprobe 子进程要等确认退出并回收后才释放调度和后台预算，关停时也会等探测会话和子进程清理完。
- **取消人物任务时文件锁没放**：取消人物元数据任务会正常释放文件锁，后面的任务不再等锁等到超时。
