# ADR-002：SQLite WAL

- 状态：已接受（规格建议）
- 日期：2026-08-02

## 决定

首版使用单文件 SQLite，开启外键、WAL 和 `busy_timeout`。数据库放在 `/config` 的本机持久化卷，不放在 SMB/NFS 上。

## 原因

Lux 是单实例、前台高读、后台短批量写的 NAS 服务。SQLite 的运维成本低，60,000 级媒体规模在合理容量内，WAL 可让读写更适合并行。

## 后果

SQLite 只有一个写者，扫描和任务系统必须使用短事务、批量写入、有界并发和受控 checkpoint。多实例共享数据库不在首版范围内。
