# ADR-014：统一元数据资源目录

- 状态：已接受（本任务实施范围）
- 日期：2026-08-11

## 背景

Lux 当前把媒体图片写回媒体目录，把人物缓存写入 `/config/people`。随着人物、合集、类型、
工作室、标签和章节缩略图增加，资源分布会变得不一致，也不利于配置卷备份、迁移和故障修复。
Emby 的 `/config/metadata` 目录提供了可借鉴的按对象分组和分片方式。

## 决定

- Lux 管理的元数据资源统一位于 `/config/metadata`。
- `library/<shard>/<item-id>/` 存放 Lux 管理的媒体条目图片、章节缩略图和后续资源。
- `people/<bucket>/<display-name>-<provider>-<provider-id>/` 存放人物头像和 `person.nfo`。
- `collections`、`genres`、`studios`、`tags` 使用
  `<kind>/<bucket>/<display-name>-<provider>-<object-id>/` 的对象目录模式，按后续任务逐步启用；
  当前只确定路径合同，不代表这些对象已经进入数据库或 API。
- 文件系统只保存资源和可迁移快照；媒体筛选、人物关系和对象索引仍由数据库负责。
- 媒体目录中的现有 NFO 和本地图片继续遵守 ADR-005，不因新增配置卷目录而自动迁移或降低优先级。
- 由 Lux 在线刮削或后台任务新生成的图片优先写入 metadata/library；媒体目录仍作为本地图片输入和
  兼容资源位置。
- 新布局采用新路径优先、旧路径兼容读取、后台可重建的迁移策略；不在请求路径扫描整个 metadata 目录。

## 路径规则

- 媒体条目使用稳定的 Lux item ID，不使用标题或媒体文件名作为身份；目录前增加稳定分片，避免
  单目录堆积大量文件。
- 人物目录名称只用于可读性，真实身份必须包含 provider 和 provider ID；展示名经过受限清洗，
  不得产生路径穿越或控制字符。
- 辅助对象目录名称同样只用于可读性，使用展示名首字符桶分散目录；真实身份必须包含 provider
  和 object ID，provider 与 object ID 必须是受限 ASCII 路径组件。
- 对象主图使用 `folder.<ext>`；人物资料快照使用 `person.nfo`。文件写入采用临时文件、同步和
  原子替换。
- 媒体条目的 `people.json` 使用带版本的 envelope 保存关系快照和 NFO 内容指纹；每个演员的
  `pendingAssets` 只记录人物目录、人物 NFO、头像或索引等可独立重试的资源失败。旧版数组格式
  继续只读兼容。
- 辅助对象的可重建描述使用对应的 `<kind-singular>.json`，例如合集使用 `collection.json`；
  这些快照不能替代数据库关系，也不作为请求路径上的扫描索引。

## 后果

- 备份 `/config` 时，数据库和 Lux 管理的元数据资源集中管理。
- 图片、人物资料和章节缩略图可以独立校验、清理和重建。
- 旧版本目录需要保留兼容读取，直到迁移任务确认新文件完整。
- 元数据目录不是媒体库，不参与媒体文件扫描，也不能替代数据库关系查询。
- NFO 丰富字段快照同时保存 NFO 内容指纹。文件只改变时间戳而内容不变时，后台会重新解析基础字段
  但复用原有丰富 JSON；内容确实变化时才重建快照。详情请求遇到损坏的派生 JSON 会清除该行并返回
  其余条目的部分结果，不把原始 NFO 当作请求时的修复输入。
