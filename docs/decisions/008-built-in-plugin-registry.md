# ADR-008：内置元数据插件注册表

## 状态

已接受。

## 背景

媒体库需要在管理员界面选择元数据刮削器，TMDb 也需要能够被单独启用。直接把 TMDb 分支散落在媒体库 API 和扫描流程中，会让后续增加其他元数据提供方时继续修改公共流程。另一方面，首版服务是单个 Rust 进程，加载任意 native、脚本或远程插件会扩大信任边界和故障面。

## 决策

Lux 使用只包含服务端已编译实现的插件注册表。插件通过稳定字符串 ID 描述能力和配置状态；插件安装状态持久化到 SQLite。媒体库保存可空的 `scraperId`，只有已安装、已启用且配置完整的插件可被选择。

首个插件为 `tmdb`，继续复用现有 `TmdbClient`。插件目录和安装状态只向管理员暴露；不支持任意外部代码的下载、动态加载或执行。

## 后果

- 新刮削器只需新增内置注册项和实现，不需要改变媒体库 API 的概念。
- 进程升级时插件实现随服务端一起升级，避免插件 ABI 和供应链问题。
- 首版不能通过上传第三方包扩展能力；如果未来需要，必须另写安全模型和 ADR。
