# ADR-004：直放优先的 Web 播放

- 状态：已接受；服务端播放细节由 ADR-026 补充
- 日期：2026-08-26

## 背景

Lux 的主要使用场景仍然是个人 NAS 上的本地媒体直放，但 Web 浏览器对容器、视频编码和音频编码的支持并不一致。
首版“只直放”的约束已经不足以覆盖 Web 播放需求，因此现在允许为本地文件创建受控的服务端播放会话。

## 决定

Lux Web 对每次播放按 0～4 档从低成本到高成本选择方案：

- 档位 0：原始媒体 Range 直放；浏览器端 HEVC/MKV fallback 仍属于这一档。
- 档位 1：视频和音频 `copy` 的 fMP4/CMAF HLS Remux。
- 档位 2：视频 `copy`、音频转为浏览器可用格式的 HLS。
- 档位 3：使用管理员明确配置且运行时可用的硬件编码器进行 HLS 转码。
- 档位 4：使用 Jellyfin FFmpeg 的软件编码器进行 HLS 转码。

本地媒体始终优先尝试档位 0，只有浏览器无法消费原始媒体时才进入档位 1～4。档位 1～4 使用独立的 Web
播放会话、短期签名 URL、有界临时目录和受限的 FFmpeg 进程；不会生成永久转码副本。

`.strm` 永远只允许档位 0。URL 型目标只能由浏览器通过受保护入口有限重定向到最终地址；直连、重定向或浏览器消费失败时直接返回明确错误。
Lux 不代理 `.strm` 的媒体字节，也不对远程目标运行 `ffprobe`、Remux 或任何音视频转码。

运行时统一使用 Jellyfin 官方 `jellyfin-ffmpeg` 项目的最新正式 FFmpeg 7 Release `v7.1.4-3`，按目标架构安装 Debian
Trixie `.deb`。`ffmpeg`、`ffprobe`、缩略图、章节检测和 HLS 执行器均通过 `/usr/lib/jellyfin-ffmpeg` 使用这套版本，
不安装普通 Debian `ffmpeg`。

## 原因

直放仍然是最省资源、延迟最低且最能保留原始质量的路径；服务端 HLS 只在 Web 兼容性确实需要时按会话启动。
将 `.strm` 排除在服务端处理之外，可以保持其直连语义，避免远程凭据泄露、SSRF、隐私和不受控资源消耗风险。

## 后果

- 本地媒体现在可以在浏览器中通过 Remux、音频转码或视频转码播放，但服务端必须承担进程、磁盘、并发和回收治理。
- 档位 3 只有在 `LUX_HLS_HW_ENCODER` 指向允许的编码器且 NAS 设备/驱动已正确映射时才可用；不能仅凭 FFmpeg 编译选项宣称硬件转码可用。
- 档位 4 受独立并发上限和临时目录配额限制，避免单个高分辨率任务拖垮 NAS。
- 播放地址由 Web 专用会话 API 产生，Emby 路由、DTO 和播放语义保持隔离。
- 外挂字幕继续通过现有字幕端点提供；本 ADR 不新增字幕格式转换、烧录、DRM 或多码率自适应 HLS。
