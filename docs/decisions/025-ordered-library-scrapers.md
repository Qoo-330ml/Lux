# ADR-025：有序媒体库刮削器与角色化执行

## 状态

Accepted

## 背景

Lux 原先每个媒体库只保存一个 `scraperId`。实际部署中，不同刮削器的覆盖范围不同：一个来源适合确定媒体身份，另一个来源可能拥有额外演员、图片或制作信息。单纯的失败回退无法补充主来源已经返回但仍缺失的字段；无规则地合并多个来源又会覆盖本地数据或改变媒体身份。

## 决策

1. 以 `library_scrapers(library_id, scraper_id, position, role)` 保存媒体库刮削器列表；`role` 为 `PRIMARY`、`SUPPLEMENT`、`BACKUP` 或 `BOTH`。
2. position 0 必须是唯一的 `PRIMARY`。后续项按 position 排序，不能重复选择同一插件。
3. `PRIMARY` 先处理本轮请求的全部能力；某项能力为空、无效、不支持或重试失败时，`BACKUP` 按 position 逐项接管。尚未确认身份时，备用来源才参与身份匹配；备用阶段已经填满的能力不再由后续备用来源重复处理。
4. 身份确认后使用 `SUPPLEMENT` 和 `BOTH`：单值字段只填空，多值字段去重追加，单图类型不覆盖已有图片，背景图按 URL 去重后按索引追加；补充来源不得改变媒体身份。`BOTH` 即使已经在备用阶段使用，仍可在补充阶段提供额外列表和背景图。
5. 每个最终字段、图片和 provider ID 记录实际来源；旧 `libraries.scraper_id` 保留为首位兼容镜像，旧 API 继续可读写单个主刮削器。

## 执行示例

假设媒体库按顺序配置：`TMDb=PRIMARY`、`豆瓣=BACKUP`、`IMDb=SUPPLEMENT`。

- TMDb 返回标题、年份、简介和演员，但没有返回海报：接受 TMDb 已返回的内容，只向豆瓣请求海报；豆瓣不能改写 TMDb 的标题、年份或简介。
- TMDb 返回完整结果：不调用纯 `BACKUP` 豆瓣。若配置了 `SUPPLEMENT` IMDb，身份确认后仍可调用 IMDb，以补充演员、类型、制作公司和背景图。
- TMDb 完全无法搜索到候选：豆瓣才接管身份搜索。豆瓣确认身份后，后续来源只能围绕这个已确认条目工作，不能另选一个条目。
- 主来源和补充来源的多值数据分别有 10 个和 10 个元素，其中 8 个相同、2 个不同：保留主来源的 10 个并追加补充来源的 2 个，最终得到 12 个；同一元素按 provider ID 或规范化文本去重。
- 单值字段不是这样相加：如果 TMDb 已有 `plot`，IMDb 返回不同的 `plot` 也不覆盖；只有 TMDb 的 `plot` 为空时，IMDb 才填入它。系统不生成“来源冲突”待处理项，也不要求管理员选择。
- poster、logo、thumb 等单图类型只保留优先级更高且已存在的图片；背景图属于可多张类型，按 URL 去重后写为 `backdrop.jpg`、`backdrop1.jpg`、`backdrop2.jpg`，与 Emby 命名保持一致。历史 `fanart.jpg`、`fanart-1.jpg` 只作为读取兼容。

## 选择理由

- 将“备用”和“补充”分开，避免主来源成功后仍无意义地调用纯备用来源。
- `BOTH` 允许一个来源同时承担两种职责，不需要在列表中重复配置。
- 角色化列表比单独维护备用列表和补充列表更容易理解，也能保留用户可见的排序。
- 领域层按字段合并，符合本地 NFO 优先和锁定字段不覆盖的既有规则。

## 后果

- 任务执行可能访问多个外部来源，因此 `FILL_MISSING` 必须先计算缺失字段/图片并复用缓存。
- 在线背景图保存来源 URL，用于跨来源去重；历史本地图片没有来源 URL 时仍按原有本地优先规则读取。
- provider ID 仍使用 provider namespace，不得将插件 ID 当作 provider ID。
- 候选和来源状态需要在任务日志中脱敏记录，不能输出外部 URL 或凭据。
- 不比较不同来源的值是否“冲突”，也不增加人工确认步骤；同一单值字段按本地/主/备用/补充优先级保留已有值，多值字段合并后保留高优先级来源顺序。
- 未来如需对不同字段配置更细的来源优先级，应新增策略模型，不改变本 ADR 的角色语义。

## 兼容性

- 数据库迁移把历史单值 `scraper_id` 转换为 position 0 的 `PRIMARY`。
- Lux API 新增有序 `scrapers` 字段，同时返回旧 `scraperId` 首项字段。
- Emby 兼容接口不暴露角色化配置，也不改变其既有 provider ID 响应合同。
