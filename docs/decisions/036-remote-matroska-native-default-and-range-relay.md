# ADR-036：远程 Matroska 原生播放默认与字幕按需 Range Relay

## 状态

已接受（修复字幕管线回归）。部分取代 ADR-035 的“远程 Matroska 默认客户端单管线”和“客户端失败即终止播放”部分。

## 背景

字幕管线发布后，PlayerPage 把所有远程 Matroska STRM 自动切换到 JavaScript Range/MSE 引擎，并延迟原生 `<video>` 的媒体 URL。
这改变了原本已经可用的远程 Direct Play 路径：远程 CDN 的 Range/CORS/索引或 MSE 任一条件不满足，视频也会显示“播放器引擎失败”。

原生 `<video>` 跟随 Lux 的签名 URL/上游 302 不需要页面脚本读取 CDN 字节；只有页面要自行解封装字幕时才需要脚本读取字节。

## 决定

1. 远程 HTTP(S) STRM 默认保持原生播放。没有显式选择远程内嵌文本字幕时，不启动客户端 Matroska Range/MSE 管线，优先沿用播放计划提供的 `proxyUrl`；只有代理路径失败时，才按既有顺序回退到签名 Lux Direct URL。这样不改变字幕改动前的媒体 URL、播放会话或回退策略。
2. 只有用户选择支持的远程内嵌 SRT/ASS/SSA 后，才按当前播放会话启用客户端字幕管线。字幕管线失败时清理自身并恢复原生视频，显示“远程字幕不可用”，不把视频标记为引擎失败。
3. 客户端字幕管线使用同源播放会话 Range Relay：
   - 仅接受有效播放会话签名和单个 `Range`；
   - 上游请求保持串行、单区间和最大 32 MiB；
   - 返回并校验 `206`、`Content-Range`、长度、`ETag`；
   - 不落盘、不缓存整部媒体、不生成外挂字幕、不调用 ffmpeg；
   - URL/path STRM、SMB/FTP、依赖远端 Cookie 或自定义认证的资源不进入该管线。
4. 远程字幕选项在 UI 中可见但不参与默认字幕选择；用户选择后才切换引擎。未满足 Relay、索引或 codec 条件时，字幕项保持不可用状态并保留原生播放。

## 后果

- 恢复字幕功能改动前远程视频的播放兼容性。
- 支持无 CORS CDN 的远程内嵌文本字幕，但增加了受会话签名保护的有限服务端字节转发。
- Relay 成为远程字幕管线的唯一读取入口；原生视频播放仍不经过 Relay。显式字幕管线失败后，播放器必须撤销字幕选择并回到同一播放计划的原生 `proxyUrl`，不得把失败升级为播放器引擎错误。
- 需要分别测试“无字幕原生播放”和“显式字幕客户端管线”，避免字幕能力再次改变默认播放引擎。

## 验证

- 远程 MKV 无字幕选择时没有 Range Relay 请求，原生 `<video>` 能播放。
- 选择 SRT/ASS/SSA 时只出现同源 Relay Range 请求，无 `/subtitles/...` 请求和第二条原生媒体连接。
- Relay 错误、索引错误、MSE 错误只禁用字幕并恢复视频；本地客户端 remux 仍能产生字幕 cue。
