# ADR-042：按物理目录触发局部增量扫描

- 状态：已接受
- 日期：2026-09-18

## 背景

Symedia 在媒体文件落入 Emby 可见目录后，会先取得媒体库中的具体目录条目，再调用
`POST /Items/{folderId}/Refresh`。Lux 原有文件监听已经能处理局部 `INCREMENTAL_SCAN`，但 Emby
兼容层没有提供目录枚举和目录刷新映射；把刷新请求直接转换成整库调和会放大扫描成本，也无法及时
覆盖监听关闭或外部同步场景。

## 决定

1. `GET /Library/MediaFolders` 返回 Lux 已索引的 `FOLDER` 条目，而不是重复返回媒体库
   `VirtualFolder`。结果支持媒体库筛选和服务端分页，并提供 `Path` 供外部同步工具进行路径匹配。
2. `POST /Items/{folderId}/Refresh` 只解析 FOLDER 的
   `folder:{library_root_id}:{relative_path}` 身份，将该相对路径加入现有
   `scan_job_paths`，复用已有增量扫描 worker、去重、取消、后处理和 webhook 生命周期。
3. 如果调用方只掌握媒体库 ID，刷新请求按该媒体库所有配置根目录加入 `.` 根目录级增量路径作为兜底；
   这仍是增量扫描，不是 `RECONCILIATION_SCAN`，并且在后台异步执行。
4. 新目录尚未有 FOLDER 条目时，使用 Lux 管理接口
   `POST /api/v1/admin/libraries/{libraryId}/scan-path`，提交受校验的根目录内相对路径；接口不
   接受绝对路径、`.`、`..` 或非递归模式。

## 备选方案

### 每次 Emby Refresh 都做整库调和

实现简单，但会遍历无关目录、增加大库延迟，并违背局部刷新和实时扫描资源隔离要求，拒绝。

### 只返回媒体库根 ID

可以兼容最简单的客户端，但外部工具无法定位已登记的具体目录，最后仍会触发近似整库扫描，拒绝。

### 为外部工具新增独立扫描队列

会复制已有去重、资源锁、后处理和任务状态逻辑；现有增量队列已经具备所需语义，因此不新增队列。

## 安全与后果

- 两个 Emby 兼容端点只允许服务器管理员或共享管理员 API Key；普通 Emby 用户返回 403。
- 路径接口只接受媒体库根目录下的规范化相对路径，FOLDER 身份在入队前再次校验根目录归属和媒体库启用状态。
- `MediaFolders` 的路径是管理员兼容接口中的已有根路径/索引路径信息；普通媒体目录查询仍使用现有安全路径投影。
- 刷新接口返回 202，扫描在后台执行；调用方应通过任务状态或后续媒体库查询观察完成结果。
