# ADR-022：Emby 单向迁移插件边界

- 状态：建议接受
- 日期：2026-08-21

## 决定

Lux 通过独立进程插件 `org.lux.emby-migration` 提供单向 Emby → Lux 数据迁移。
Lux 永远不提供反向迁移，也不读取或修改 Emby 内部数据库。

插件负责公开 Emby API 的连接、分页采集和第三方响应校验；Lux 宿主负责用户、媒体和权限映射，
持久化迁移任务、写入用户状态、保存播放历史事件以及报告和恢复。

## 原因

- 独立进程保持插件不能访问 Lux 数据库、媒体目录和内部任务对象的现有安全边界。
- 公开 API 不提供可移植的 Emby 密码哈希，因此采用首次登录时向 Emby 验证一次原密码，再在 Lux
  本地创建密码哈希。
- Emby 版本可能只提供条目级 UserData，而不提供完整播放事件流。协议显式区分
  `ITEM_STATE` 和 `EVENT_HISTORY`，避免用聚合数据伪造时间线。
- 迁移任务必须可预览、幂等、可取消和可恢复，不能由 HTTP handler 直接执行整库采集或写库。
- 迁移范围由宿主显式建模。支持 `supportsFilteredReads` 的插件必须在来源端应用已选用户、来源虚拟库和
  UserData 字段投影；旧插件不接收这些可选字段，宿主只保证目标端的写入白名单，避免破坏旧插件的严格参数解析。
- 媒体匹配按页查询候选，Provider ID 使用规范化索引，标题/年份只作有界回退；坏页恢复设置每个逻辑页最多 32 次来源 RPC，
  超出预算时以可诊断的范围跳过并推进持久化游标。

## 数据安全

- Emby 基础地址、API key 和局域网访问许可由 `org.lux.emby-migration` 插件设置页面管理；API key
  保存在受保护的插件配置中，测试连接或创建任务时由宿主读取并校验。创建任务后，宿主把经过校验的
  来源快照写入任务专属受保护 secret，插件调用时临时传递。API key 不进入普通 API 响应、日志或插件包。
- 用户首次登录密码只在内存中用于一次 Emby 验证，成功后立即转换为 Lux 本地密码哈希。
- 日志和错误响应不得包含 API key、密码、token、完整外部 URL 或原始 Emby 响应。
- 所有 Emby 返回值视为不可信输入，必须先做大小、类型、枚举、时间和 ID 校验。

## 后果

- Plugin SDK 需要新增迁移插件类型和能力合同。
- Lux 需要新增持久化迁移任务、映射、导入记录和播放历史事件模型。
- 在公开 API 无法提供事件历史的 Emby 版本上，只能保证条目状态迁移；该限制必须展示在预览和结果报告中。
