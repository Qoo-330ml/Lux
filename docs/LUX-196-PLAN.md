# LUX-196：有序媒体库刮削器角色与补充策略

## 目标

一个媒体库可以配置多个已安装刮削器，并按顺序和角色运行：首位为主刮削器，后续刮削器可作为补充、备用或两者兼具。旧版单值 `scraperId` API 和数据库字段继续兼容。

## 角色合同

- `PRIMARY`：只能位于 position 0，负责确定媒体身份和提供最高优先级在线元数据。
- `BACKUP`：主来源无法确定身份时，按顺序尝试；成功后成为本次实际匹配来源。
- `SUPPLEMENT`：身份确定后只填充缺失的未锁定字段和缺失图片类型。
- `BOTH`：同时具备备用和补充行为。

字段优先级为本地锁定字段、本地 NFO/图片、主/实际匹配来源、后续补充来源、文件名/探测回退。后续来源不能改变已确认媒体身份。

## 实施切片

### Slice 1：规格、ADR 和迁移

- 更新 `docs/LUX-DEVELOPMENT.md`。
- 新增 ADR-025，记录列表模型、角色语义和兼容策略。
- 新增 SQLite/PostgreSQL `library_scrapers` 表，历史 `libraries.scraper_id` 回填为首位 `PRIMARY`。

### Slice 2：存储和领域配置

- 增加有序刮削器读写、角色校验和旧字段镜像。
- 更新媒体库领域模型、扫描计划和插件卸载清理。
- 记录实际成功 scraper 来源，供图片、合集和后续刷新使用。

### Slice 3：Lux 管理 API

- 新增 `scrapers` 输入/输出字段。
- 保留 `scraperId` 的单值读写兼容。
- 管理员创建和 PATCH 使用原子列表更新，并验证安装、启用、可用状态。

### Slice 4：刮削编排和合并

- `PRIMARY`/`BACKUP`/`BOTH` 实现按序身份匹配。
- `SUPPLEMENT`/`BOTH` 实现缺失字段和图片类型补充。
- 扩展字段、图片、provider ID 和候选来源追踪。

### Slice 5：Web 管理界面

- 多刮削器拖拽排序。
- 后续项角色选择。
- 首位自动固定为主刮削器。
- 保留暂不可用的已选项并显示错误状态。

## 验证

- Rust：相关单元/集成测试、迁移空库测试、全量 build/test/fmt/clippy。
- Web：单测、构建和关键管理流程测试。
- 记录 `uname -m`；本机 ARM64 结果不代表 NAS/x86 性能。

## 明确不做

- 不修改 Emby 兼容 DTO 的既有单值字段语义。
- 不让补充刮削器自动覆盖本地或锁定元数据。
- 不在用户请求路径同步执行多刮削器网络请求。
- 不新增转码、代理播放或其他未相关功能。
