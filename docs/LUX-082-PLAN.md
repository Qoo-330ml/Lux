# LUX-082 首页聚合

## 范围

提供一次 Lux 首页请求所需的继续观看、媒体库入口和每个媒体库的最新资源横栏，并补齐 Emby Latest；继续观看和最新资源使用现有用户状态和媒体库 ACL。

## 实现

- [x] 新增 `GET /api/v1/home`，返回继续观看摘要和可见媒体库入口。
- [x] 首页每个可见媒体库入口返回最多 12 条按 `added_at` 倒序的 `latest` 资源，避免前端逐库请求。
- [x] 新增 `GET /Users/{userId}/Items/Latest`，复用 ACL、筛选和稳定排序路径。
- [x] Latest 使用 DateCreated/UUID v7 倒序作为当前稳定的最近添加排序。
- [x] 首页继续观看同时包含有未完成进度的电影和剧集单集，并返回当前用户的播放位置。
- [x] 首页的媒体库入口和每库最新资源使用进程内缓存，并在扫描失效后后台刷新。
- [x] 首页缓存按用户 ID、管理员状态和可访问媒体库隔离；媒体库首屏缓存按用户、媒体库、筛选、排序、offset 和 limit 隔离。读取缓存前必须完成当前请求的 ACL 校验。
- [x] 首页和媒体库缓存使用有限条目数与短 TTL stale-while-revalidate；过期请求先返回最近快照，由有界后台刷新任务更新。
- [x] 扫描、媒体删除、媒体库权限或媒体库启停变化会使相关缓存失效；短时间连续失效合并为一次刷新。

## 验证

- 既有 NextUp、Resume、目录和 ACL 集成测试保持通过。
- 全量 ARM64 回归覆盖首页相关路径。
- 首页和媒体库缓存命中、过期 stale、后台刷新和失效行为有自动化测试。
- SQLite/PostgreSQL 首页查询索引从当前最高迁移版本追加，不重排已有迁移。

## 明确不做

- 不引入数据库持久化缓存；进程重启后缓存丢失并按需或后台预热重建。
- 缓存键不得省略用户身份、管理员状态、媒体库 ACL、筛选条件或分页参数；不得在 ACL 校验前直接返回缓存内容。
